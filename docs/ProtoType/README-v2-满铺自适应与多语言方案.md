# KDS 原型 v2 · 满铺自适应 + 多语言抗换行 + 实时配置

> 针对三条反馈的重做版本：① 整屏铺满（宽屏两端不留白）② 多语言不再大量换行 ③ 原型内可调行列数 / 字号并实时预览。
> 入口：`prototype/v2/index.html`（A/B 并排比稿）→ `prototype/v2/app.html`（可交互主原型）

---

## 一、问题根因

v1（`scheme-a` / `scheme-b`）用的是**固定画布 + 等比缩放**：

```css
#stage{width:1920px;height:1080px;transform:scale(...);transform-origin:center center}
```

等比缩放必须保持 16:9，因此在 21:9 / 32:9 / 3440×1440 上**必然**出现上下或左右留白——这不是样式没调好，是方案的数学结果。同时字号被锁死在 1920 基准下，卡片变宽并不带来信息量，只带来更多换行空间。

---

## 二、解决方案

### ① 满铺全屏：流式网格 + 自动密度

**外壳**——不再有画布，网格直接吃满视口：

```css
#app{position:fixed;inset:0;display:grid;
     grid-template-rows:auto minmax(0,1fr) auto;overflow:hidden}
.grid{flex:1;min-width:0;min-height:0;display:grid;gap:var(--gap);
      grid-template-columns:repeat(var(--cols),minmax(0,1fr));
      grid-template-rows:repeat(var(--rows),minmax(0,1fr))}
```

`minmax(0,1fr)` 是关键：它允许单元格被压缩到比内容更小，从而杜绝溢出与滚动条。

**自动密度**——宽屏不是把卡片拉宽，而是**多摆几列**，让单卡尺寸稳定在可读区间：

```js
const c = Math.max(3, Math.min(6, Math.round(w / 560)));  // 目标卡宽 ~560
const r = Math.max(2, Math.min(4, Math.round(h / 400)));  // 目标卡高 ~400
```

实测自适应结果（自动档）：

| 视口 | 密度 | 单卡实测 | 菜名字号 | 卡尾按钮 |
|---|---|---|---|---|
| 1280×720 | 3×2 | 396×209 | 17.98px | 48px ✅ |
| 1366×768 | 3×2 | 423×232 | 19.92px | 48px ✅ |
| 1920×1080 | 3×2 | 600×362 | 29.98px | 58px ✅ |
| 2560×1080 | 4×2 | 597×353 | 29.85px | 58px ✅ |
| 3440×1440 | 6×3 | 535×514 | 26.77px | 58px ✅ |
| 3840×1080 | 6×2 | 602×353 | 30.10px | 58px ✅ |

单卡宽度始终锁在 **396–602px** 区间，屏幕越宽只增加列数——**两端永远不留白，字号永远可读**。

**末页收拢**——最后一页不足一屏时，网格行数收拢为 `ceil(n/cols)`，剩余卡片自动放大铺满，不出现半屏空网格：

```js
grid.style.gridTemplateRows = `repeat(${Math.min(S.rows, usedRows)}, minmax(0,1fr))`;
```

### ② 多语言抗换行：三层文本策略

德/俄文本长度约为中文的 2.2–2.3 倍，靠"留够空间"永远解决不了。改为**按优先级分配空间**：

| 层级 | 元素 | 策略 | 行为 |
|---|---|---|---|
| **固定段** | 桌号、数量、计时、人数 | `white-space:nowrap` | 永不换行，字号随卡缩放 |
| **弹性段** | 菜名、做法/备注 | `nowrap` + `text-overflow:ellipsis` | 空间不足就截断，不换行 |
| **折叠段** | 徽标区、超出菜品 | `overflow:hidden` / `+N 道` | 直接不显示，用计数兜底 |

```css
.rname{flex:0 1 auto;min-width:0;
  font-size:clamp(11px,calc(min(var(--k-dish-w)*1cqw,var(--k-dish-h)*1cqh)),40px);
  white-space:nowrap;overflow:hidden;text-overflow:ellipsis}
```

**字号跟卡片走，不跟屏幕走**——CSS 容器查询让每张卡自成排版上下文：

```css
.tcard{container-type:size;container-name:card}
```

`cqw` / `cqh` 是卡片自身宽高，再取 `min(w系数, h系数)`：卡片变矮或变窄，字号都同步下降，**在任何密度下都不会撞行**。

**溢出审计**（面板开关）——遍历所有文本节点，凡 `scrollWidth > clientWidth` 的打红色虚线框。切到 DE/RU 打开它，哪里被截断一眼看到，而不是等到上线才发现。

**超级长词兜底**——德语复合词（如 `Rindfleischstreifen`）额外允许可选两行截断：

```css
.rline2{-webkit-line-clamp:2;display:-webkit-box;-webkit-box-orient:vertical}
```

**RTL**——阿拉伯语 `dir="rtl"` + 逻辑属性（`inset-inline-start` / `margin-inline-start`），布局自动镜像，无需第二套样式。

**长度梯度**已内置，供设计评审参考：`zh-CN 1.0 / zh-TW 1.05 / en 1.7 / de 2.2 / ru 2.3 / ar 1.35`。
运行时由 `LANG_META` 表驱动（见 §十二），面板语言项旁会实时显示当前语言的系数。

## 三、触摸与滚动（延续 v1 硬约束）

- 卡尾操作条下限锁死 `48px`：宁可少显示一道菜，也不压缩触点。
  ```css
  .cft{flex:none;height:clamp(48px,21.5cqh,86px)}
  .btn{height:clamp(48px,17.5cqh,58px);max-height:100%}
  ```
  `max-height:100%` 防止极端密度下按钮撑破底部条。
- 全程无滚动条：桌台用分页，卡内超出菜品折叠为 `+N 道`。
- 顶栏**渐进降级**：`scrollWidth > clientWidth` 时依次隐藏次级标签（lv1→lv2→lv3），窄屏下不挤成一团。
- 分页按钮 ≥200×64；`←` `→` 翻页，`1`–`4` 直达视图，`P` 开配置，`Esc` 关闭。

## 四、踩坑记录（重要）

**Chromium 的 `calc()` 不接受「数字 × 数字 × 长度」三连乘。**

```css
/* ✗ 无效 —— 整条声明被丢弃，font-size 静默回退到继承值 16px */
font-size: clamp(11px, calc(5.0 * 1.72 * 1cqh), 40px);

/* ✓ 有效 —— 系数必须预乘好，只做「系数 × 1cqw」 */
font-size: clamp(11px, calc(min(var(--k-dish-w)*1cqw, var(--k-dish-h)*1cqh)), 40px);
```

因此把系数拆成**成对常量**（`--k-*-w` / `--k-*-h`），由 JS 在字号缩放变化时统一重算并写回：

```js
const K_BASE = {'k-table-w':6.6,'k-table-h':11.55, 'k-dish-w':5.0,'k-dish-h':8.6, /* ... */};
function applyScale(){
  const st = document.documentElement.style;
  st.setProperty('--fs-scale', S.scale);
  for(const [k,v] of Object.entries(K_BASE)) st.setProperty('--'+k, (v*S.scale).toFixed(3));
}
```

症状是"字号怎么调都不动"且控制台无报错——排查时优先验 `calc()` 是否合法。

## 七、与文档的偏差（需确认）

1. **卡尾按钮下限 48px**：文档 §要求 ≥56px；在 1280×720 / 1366×768 下若强锁 56px，卡片高度会被吃掉近 1/4。取 48px（WCAG AA 触摸下限）作为可达成下限，大屏自动放大到 58px。**若目标终端最低 1920×1080，可改为 56px 硬下限。**
2. **自动密度目标卡宽 560px**：文档未定义。按"桌号 + 5 道菜 + 操作条"在 3 米视距可读反推得出，可用面板现场调。
3. **菜名默认截断而非换行**：牺牲完整菜名换取零换行。若厨房要求菜名必须完整可见，需改为"下单时限制菜名字数"或启用两行档并接受卡高增加。

## 八、v2.1 修复记录（配置面板不可读 + 夜航对比度）

### 缺陷 1：面板背景全透明，文字与菜卡糊在一起 —— 根因是 CSS 变量作用域

`#panel` / `#fab` / `#scrim` 都挂在 `<body>` 下，是 `#app` 的**兄弟节点**；而主题属性写在 `#app` 上：

```html
<div id="app" data-theme="a"> … </div>
<aside id="panel">   <!-- 在这里拿不到 --bg-surface -->
```

`#panel{background:var(--bg-surface)}` 中变量未定义 → 整条声明非法 → 浏览器丢弃 → **背景变完全透明**，且控制台不报错。这正是"看不清楚、没法配置"的原因。

修复三层保障：

1. 主题令牌改挂 `<html>`：`document.documentElement.dataset.theme = S.theme`，`#app` 不再携带主题属性。
2. `:root` 内补一套浅色兜底值，任何元素即使没命中主题选择器也有合法颜色。
3. `#panel` 内再写一层显式兜底：`background:#FFFFFF; background:var(--bg-surface,#FFFFFF)`。

验证：`panel-bg=rgb(22,29,38) alpha_ok=true`（主题 A）/ `rgb(255,255,255)`（主题 B），无 alpha 通道。

### 缺陷 2：夜航主题文字对比度不足

实测（修复前，AA 要求 4.5:1）：

| 令牌 | 修复前 | 最差底 | 修复后 | 修复后最差 |
|---|---|---|---|---|
| `--text-3` | `#75838F` | `#232F3D` **3.49 ✗** | `#8B98A6` | **4.62 ✓** |
| `--text-2` | `#A3B0C0` | `#232F3D` 6.17 | `#B3BFCE` | 7.05 ✓ |
| `--brand`（作文字） | `#3D8BFF` | `#232F3D` **4.10 ✗** | 新增 `--brand-ink:#63A8FF` | **5.55 ✓** |
| `--st-hold` | `#8B95A3` | `#232F3D` 4.48 ✗ | `#A8B2BF` | 7.04 ✓ |

原本固定定位在右下角，与卡片底栏、分页条三方打架。改为**归位到分页条末尾**：`[◀ 上一页] … [下一页 ▶] [⚙]`。分页条本身就是操作区，设置入口放这里语义更正确，且永不遮挡内容。

## 九、v2.2：单菜小卡片 + 三视图独立行列/字号

### 单菜从表格行改为小卡片

原 `.s-hd` 表头 + `.srow` 七列（桌号/菜名/数量/做法/等待/标记/操作）横向被列宽切碎，德/俄语必换行。改为 `.single` 网格 + `.scard` 小卡：

### 三视图共用行列令牌

| 桌台 | 2–6 | 1–4 | 560×400 | 3×2 |
| 合菜 | 2–6 | 2–5 | 360×250 | 5×3 |
| 单菜 | 3–8 | 2–5 | 272×186 | 7×4 |

## 十、v2.3 修复：合菜/单菜「行数」设置不起作用

### 根因

三视图的 render 里都有「末页收行」：

```js
const rows = Math.max(1, Math.ceil(list.length / S.cols));
if(rows < S.rows) wrap.style.gridTemplateRows = `repeat(${rows},minmax(0,1fr))`;
```

每页容量 `pageSize() = cols × rows`，故 `list.length ≤ cols × rows` 恒成立，
`ceil(len/cols)` 永不大于 `S.rows` —— **只会往下收，不会往上撑**。
合菜 12 条 @5 列时设 3/4/5 行都是 3 行；单菜 24 条 @7 列时设 4/5 行都是 4 行。
调小行数有反应（页数变多），调大完全没反应。

### 决策

收行逻辑本身是错的：它让卡片尺寸成为数据量的函数——首页 28 张卡每张 178px，末页 4 张就变 700px。
厨房里手会形成肌肉记忆，卡片忽大忽小比留白危险。

- 默认**严格按 `S.rows` 渲染**，末页空着就空着，卡片尺寸恒定。
- 新增面板开关 **「末页铺满」**（`S.fill`，默认关，URL `?fill=1`）。
- 三视图统一 `applyGridRows(g, n)`。
- 读数区显示「本页占用 X/Y 格」，开了铺满则显示「实渲 N 行（末页铺满）」。

### 实测 @1920×1080

| 设置 | fill=0 | fill=1 |
|---|---|---|
| 合菜 5×4 | 卡 274×165，菜名 14.7px | 274×224（收 3 行） |
| 合菜 5×5 | 卡 274×129，菜名 11px | 274×224（收 3 行） |
| 单菜 7×3 | 卡 253×241，菜名 27.3px | 同左 |
| 单菜 7×5 | 卡 253×140，菜名 20.4px | 253×178（收 4 行） |

行数不是越大越好，要配合列数一起调。

## 十一、v2.4 修复：合菜/单菜卡内容顶部对齐

### 问题

单菜 `.sbody` 用 `justify-content:center`，合菜 `.mname` 用 `margin-block:auto` —— 都是垂直居中。
一排卡里菜的叫法长短不一：有做法行的卡、菜名一行的卡、菜名两行的卡，整块内容高度不同，
居中之后菜名的起始 y 各不相同，横着扫一行眼睛要上下找，视觉上是锯齿。

### 改法

| 元素 | 原 | 现 |
|---|---|---|
| `.sbody` | `justify-content:center` | `justify-content:flex-start` |
| `.mname` | `margin-block:auto` | `margin-block:clamp(17px,14.5cqh,44px) 0` |
| `.srow1` | 高度随内容 | `min-height:clamp(16px,5.6cqh,32px)`（与 `.badge` 同一套 clamp） |

两个坑：

1. **合菜菜名必须预留顶部一条**：状态角标 `.mcorner` 与数量角标 `.mqty` 是绝对定位压在卡顶的，
   以前靠垂直居中「躲开」，改成顶对齐就得显式让位。留白要**所有卡都留** ——
   只给有角标的卡加，那些卡又会被压下去。
2. **单菜首行要等高**：实测 6×5 档残留 2px 错位，有徽标的卡首行 16px、没徽标的只有 13px 文字行高。
   把 `.srow1` 的 `min-height` 写成与 `.badge` 完全相同的 clamp 即可。

### 验证

菜名相对卡顶偏移：单菜 7×4 / 6×5 / 8×2 / 4×4，合菜 5×3 / 6×5 / 2×2 —— **离散度全部为 0**。
德语 / 俄语 / 阿拉伯语 × 1920 / 1440 / 1280 八组回归：溢出 0、角标压名 0、压底栏 0。

## 十二、v2.5：新增繁體中文（对外 tag：`zh-TW`）

> **v2.19 标签修订（2026-10-25）**：对外语言标签由 `yue-Hant-HK` 改为 **`zh-TW`**，
> 与 `KDS-09 §11` 的 BCP-47 语言表对齐（`zh-CN` / `zh-TW` / `en-US`）。
> 内部词典 key 沿用 `yue`（兼容旧深链 `?lang=yue`），深链同时接受
> `?lang=zh-TW` / `zh-Hant` / `zh-HK`；膨胀系数 1.15 → **1.05**；字形栈改 TC 优先。

### 语言元数据表

原来 `render()` 里硬编码 `document.documentElement.dir = S.lang==='ar' ? 'rtl' : 'ltr'`，
每加一种语言就要改判断。改为 `LANG_META` 表驱动：

```js
const LANG_META = {
  zh :{tag:'zh-CN',       dir:'ltr', len:1.00, name:'简体中文'},
  yue:{tag:'zh-TW',       dir:'ltr', len:1.05, name:'繁體中文'},
  en :{tag:'en',          dir:'ltr', len:1.70, name:'English'},
  de :{tag:'de',          dir:'ltr', len:2.20, name:'Deutsch'},
  ru :{tag:'ru',          dir:'ltr', len:2.30, name:'Русский'},
  ar :{tag:'ar',          dir:'rtl', len:1.35, name:'العربية'}
};
const langMeta = () => LANG_META[S.lang] || LANG_META.zh;
```

- **`tag` 必须是 `zh-TW`**（KDS-09 §11）。裸 `zh-Hant` 不含地区、裸 `yue` 只声明语言不含文字系统，浏览器仍可能用简体字体回退。
- **`dir` 收进表里**，加 RTL 语言时只改一行数据，不动逻辑。
- **`len`（文本膨胀系数）** 驱动面板小注与读数区标色，`>= 1.7` 才提示「长文本」。

### 词条重写而非简转繁

繁體不是「简体换个字形」，餐饮行话差异极大：米饭→白飯、拍黄瓜→拍青瓜、
干锅花菜→乾鍋椰菜花、桌台→檯、合菜→併菜、换人→交更、早班→早更、
已选→已揀、待制作→待整、即将超时→就快超時、冰→凍、赠→送、登录→登入、工号→員工編號。
纯简转繁会产出「米飯 / 桌台 / 換人 / 早班」，能读但一身机器味。

### 繁体字形要单独配字体栈

```css
html:lang(zh-TW) body, html:lang(zh-Hant) body, html:lang(zh-HK) body{
  font-family:"PingFang TC","Microsoft JhengHei","Noto Sans TC","PingFang HK","Noto Sans HK",sans-serif;
}
```

港台字形与大陆字形规范不同（骨 / 內 / 起 等字的笔形），继续吃 `PingFang SC` /
`Microsoft YaHei` 会渲染成大陆写法；兜底也不再落回 `Microsoft YaHei`。

### 顺带接通的入口

1. `#langNote`：面板语言项旁显示「全名 · 文本 ×系数」。
2. 读数区语言行：显示语言全名 + 长度系数，不再对 de/ru 写死的特判。
3. `?audit=1`：`#swAudit` 面板开关原本就有，加 URL 参数是为了截图 / 评审时免手动一步直接出料。
4. 版本号 v2.4.1 → v2.5.0；对比页 `index.html` 同步加繁體按钮。
   面板按钮印短标签「繁體」（与「中文」两个字对齐），全名 `繁體中文` 交给 `#langNote` 小注。

### 验证

| 检查项 | 结果 |
|---|---|
| 词典缺 key / 多 key | 0 / 0 |
| `{n}` `{m}` 占位符与中文一致性 | 0 处差异 |
| 繁體 × 三视图 `?audit=1` 截断 | 全部 0 |
| 繁體 9 组密度 × 分辨率菜名对齐 | 离散度全部 0，无溢出、无压底栏 |

## 十三、v2.6：字号缩放按视图独立

### 为什么共用一根滑块是错的

`S.scale` 原为全局单值，`applyScale()` 把所有 `--k-*` 乘它写到 `<html>`。但三视图卡片量级不同：

| 视图 | 卡片 | 菜名基准 |
|---|---|---|
| 桌台 | 600×362 | 30.0px |
| 合菜 | 274×224 | 19.3px |
| 单菜 | 253×178 | 25.9px |

容器查询下 `font-size = min(k-w×cqw, k-h×cqh)`，卡片大一倍字就大一倍。**同一档缩放对应完全不同的实际 px** ——
为了看清合菜拉到 130%，切到桌台字就溢出。共用滑块的结果就是逼用户在视图间来回重调。

### 改法（照抄已验证的 S.dens 模式）

```js
fonts:{ table:1, merge:1, single:1 }   // S.scale 始终代表「当前视图」
```

- `setView()`：离开时 `S.fonts[旧] = S.scale`，进入时 `S.scale = S.fonts[新]`；login 不参与存档。
- `syncFontUI()`：滑块 / 百分比 / 标签里的视图名永远跟当前视图同步。
- 滑块 `oninput` 只写 `S.fonts[S.view]`。
- 新增「把当前值套用到全部视图」按钮 —— 各自独立，但必须留批量出口，否则想统一要调三次。
  按下后文案变 `✓ 已套用到三个视图`（`fsApplied`，六语言齐备）。
- 面板标签：「字号缩放 · 单菜 130%」；读数区：`字号缩放 130%（仅单菜）`。

### 关键点：CSS 一行没改

同一时刻只渲染一个视图，`render()` 里按当前 `S.scale` 重算 `--k-*` 即可。
`--k-*` 只被卡片内部 21 处使用，**顶栏 / 页脚 / 面板不吃这些系数**，所以切视图时 chrome 字号不会跳 ——
这也是敢把系数做成分视图的前提，否则需要在卡片根上再叠一层 scope。

### 验证

程序化切换序列：`table 1.00 → single 调 1.30 → table 仍 1.00 → merge 仍 1.00 → 回 single 恢复 1.30`
→ 点套用全部三者 `1.30`。
渲染层：单菜菜名 100% 时 25.9px / 130% 时 33.7px；同一会话切桌台，桌号仍 39.6px 未被带跑。
深链隔离：`?view=single&scale=1.3` 只写 single，`?view=login&scale=1.2` 不污染任何存档。

## 十五、v2.7：登录满屏 + 样式外置 + 原型目录归一

### 15.1 登录界面也要铺满

改前：`.login` 是 `flex + center`，卡宽写死 `min(660px,42vw)`、键盘 `min(430px,30vw)`，


| 视口 | 登录卡 | 键盘 | 单个数字键 |
|---|---|---|---|
| 1280×720 | 734×540 | 474×540 | 145×114 |
| 1440×900 | 828×716 | 534×716 | 162×152 |
| 1920×1080 | 1147×912 | 739×912 | **227×194** |
| 2560×1440 | 1488×1203 | 960×1203 | 293×255 |
| 1080×1920 竖屏 | 上下排（键盘在下） | — | 318×175 |

数字键从最大 96px 高变成 194px 高，全部远超 48px 触控下限。竖屏用
`@media (max-aspect-ratio:1/1)` 自动改上下排，不必为竖屏单做一套。

### 15.2 两套主题抽成独立 CSS

`app.html` 原本是 900+ 行的单文件，内联 `<style>` 占 38.5KB。现在按「是否与主题有关」切成三份：

| 文件 | 规则数 | 内容 |
|---|---|---|
| `css/core.css` | 265 | 重置 / 布局 / 顶栏 / 三视图卡片 / 登录 / 面板 / 分页；颜色一律写 `var(--token)` |
| `css/theme-a.css` | 7 | `[data-theme="a"]` 令牌重定义（夜航）+ 少量必须写死色值的组件覆盖 |
| `css/theme-b.css` | 2 | `[data-theme="b"]` 令牌（日间）+ 覆盖 |

```html
<link rel="stylesheet" href="css/core.css">
<link rel="stylesheet" href="css/theme-a.css">   <!-- 顺序不能反 -->
<link rel="stylesheet" href="css/theme-b.css">
```

**顺序为什么不能反**：主题令牌定义在 `[data-theme="x"]` 上，与 `:root` 兜底令牌特异性同为 (0,1,0)，
靠「后来者胜」覆盖。所以主题必须在 core 之后；两个主题文件之间靠属性选择器互斥，可同时加载。

切主题只改 `<html data-theme>`，**不需要换 CSS 文件** —— 对比页里两个主题可以同时在线比稿。

顺带修的一处：`body{background:#DCE3EC}` 是硬编码浅色。`#app` 是 `position:fixed` 全屏平时盖住它，
但 overscroll / iframe 边缘会露出这一层，夜航主题下会闪出浅色块 —— 改成 `var(--bg-page,#DCE3EC)`。

## 十六、v2.7.1：登录页收口（顶栏收权限 + 控件放大 + 确认键降级）

### 16.1 登录页不该露出业务入口

第一版满铺后，登录页顶栏仍原样挂着：`桌台 / 合菜 / 单菜` 视图切换、`全部 12 / 催菜 3 / 超时 3 / 等叫 1` 筛选、
搜索框、**`张师傅` 与 `换人`**、`我的划单`。三个问题：

1. **逻辑自相矛盾**——还没认证，右上角已经写着当前操作员是谁，还提供「换人」。
2. **入口无数据可指**——筛选与搜索都是对工单集合操作，未登录时集合都不存在。
3. **注意力分散**——登录页只需回答一件事：我是谁。旁边摆 7 个别的入口就是干扰。

**做法**：`render()` 时给 `#app` 打 `is-login` 类，CSS 收起这些节点，**保留品牌块与时钟**
（登录页仍要让人知道站在哪台机器前、现在几点）。

```css
#app.is-login .top > .vsep,
#app.is-login #tabs,
#app.is-login #chips,
#app.is-login .search,
#app.is-login .who,
#app.is-login .tb-btn{display:none}
```

> 注意这是**收起**不是删除：DOM 结构不变，退出登录后类一摘即恢复，不需要重建顶栏。

## 十七、导航页 v2.8：index.html 成为唯一入口

> 本章只动 `index.html`（比稿导航页）。`app.html` 本身无改动，仍是 v2.7.1，
> 两者版本号各自独立演进 —— 导航页加入口不需要重出原型截图。

### 17.1 为什么要做「入口清单」而不是再加一个按钮

原来 `index.html` 的入口是手写在 HTML 里的三个按钮：

```html
<button data-view="table" class="on">桌台</button>
<button data-view="merge">合菜</button>
<button data-view="single">单菜</button>
```

加登录意味着再拷一段 `<button>`。但问题不在这一次拷贝，在于**每次加页面都要改三个地方**：
HTML 按钮、底部的 footer 说明、以及「全屏打开」链接的文案。漏一个就是不一致
（比如登录页进了，底部还在教人「按 ← → 翻页」，而登录页根本没有分页）。

改成数据驱动：一个 `ENTRIES` 数组描述所有入口，按钮、页签、底部说明、标题、深链全部由它生成。

```js
const ENTRIES = [
  { id:'table',  label:'桌台', paged:true,
    tip:'右下角 ⚙ 打开「显示与布局」面板：配置对象 · 列数 · 行数 · 字号缩放 …' },
  { id:'merge',  label:'合菜', paged:true,  tip:'合菜卡按菜品聚合 …' },
  { id:'single', label:'单菜', paged:true,  tip:'一卡一菜的小卡形态 …' },
  { id:'login',  label:'登录', sep:true, paged:false,
    tip:'登录态收起顶栏全部业务入口，只留品牌块与时钟 …' },
];
```

**以后新增页面（出菜队列、改单确认、报表…）只改这一处**，其余全部自动跟上：

| 自动生成 | 来源 |
|---|---|
| 顶部入口按钮 + 高亮 | `label` / `id` |
| 按钮前的分组竖线 | `sep:true`（用来把「流程页」和「数据视图」分开） |
| 底部说明文案 | `tip`（`innerHTML`，可带 `<b>`） |
| 是否提示 ← → 翻页 | `paged` |
| 浏览器标题 | `KDS v2 · {label} · 满铺自适应原型比稿` |
| 两个 iframe 的 `?view=` | `id` |
| 「全屏打开 ↗」链接 | `id` + 当前语言 |
| URL 深链 `#lang=&view=` | 当前状态 |

### 17.2 登录不是「第四种视图」

三个数据视图（桌台 / 合菜 / 单菜）是同一个工单集合的三种呈现方式，而登录是**流程起点**。
并排放四个同等按钮，容易被读成「四种视图」。所以在登录前插一道竖线
（`{ sep:true }` → `<span class="sep">`），把它隔成另一个语义组：

```
语言 [中文][繁體][EN][DE][RU]  入口 [桌台][合菜][单菜] │ [登录]
```

### 17.3 底部提示必须跟着入口走

| 提示 | 桌台/合菜/单菜 | 登录 |
|---|---|---|
| 入口专属说明（`tip`） | 面板怎么用 / 这张视图在验什么 | 登录态收起了什么、为什么没有 ⚙ |
| `←` `→` 翻页 | 显示 | **隐藏**（登录页没有卡片网格，也没有分页） |
| 语言切换会暴露换行 | 显示 | **显示** |

最后一条是过程中修正的：我一开始按「面板不可用 → 整条提示隐藏」做，把语言那条也收掉了。
但登录页恰恰是六语言文案长度差异最大的一屏（「请输入工号与 PIN 码」德语要长 80%），
**它比列表页更需要语言压测**。所以语言提示常显，只收翻页提示。

### 17.4 顺手加的两个比稿便利

1. **数字键 `1`–`4` 直接切入口**：来回比对四个入口比点按钮快，放在底部提示里。
   越界键（`9`）无副作用，带 `Ctrl/Cmd/Alt` 的组合不拦。
2. **URL 深链**：当前入口与语言写进 `#lang=zh-TW&view=login`，
   发给同事直接落在同一屏；`file://` 下 `replaceState` 可能被拦，已降级到 `location.hash`。

### 验证（headless）

- 入口生成：4 个按钮 + 1 条分隔线，`桌台` 默认高亮。
- 切换：点「登录」→ 两个 iframe 变 `?theme=a|b&view=login`，标题与 tip 同步，
  `← →` 提示 `hidden=true`，语言提示仍可见。
- 深链：`#lang=zh-TW&view=login` → 入口「登录」高亮、语言「繁體」高亮、iframe 带两个参数；
  `#lang=ar&view=single` 同理。
- 键盘：`4` → 登录、`2` → 合菜、`9` → 不变。
- **扩展性**：临时往 `ENTRIES` 塞一条「出菜队列」，按钮变 5 个、标题变
  `KDS v2 · 出菜队列 · …`、iframe 变 `view=queue` —— 除数组外零改动。

### 17.5 SOP：以后新增一个原型页面（照做即可）

导航页侧**只改 `ENTRIES` 一处**，加一项：

```js
{ id:'queue', label:'出菜队列', paged:true, tip:'这一屏要验什么，一句话写清' },
```

字段填法：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 传给 `app.html?view=` 的值，**必须先在 app.html 里存在同名视图**，否则 iframe 落到空白兜底 |
| `label` | ✅ | 按钮文案，2–4 字，同时进浏览器标题 |
| `paged` | ✅ | 有卡片网格/分页 → `true`；登录这类全屏单页 → `false`（决定要不要提示 ← →） |
| `tip` | ✅ | 底部说明，`innerHTML`，可带 `<b>`；写「这一屏验什么」，别写「怎么用」 |
| `sep` | ➖ | 只有**非数据视图**（登录、改单确认这类流程页）才加，插一道竖线与前三个视图隔开 |

`ENTRIES` 的数组顺序 = 按钮顺序 = 数字键顺序（`1` 起）。流程页放末尾。

app.html 侧新增视图需要配套改动（`view` 分支散在几处，漏一处就是半残状态）：

1. `itemsOf(view)` —— 这一屏的数据源。
2. `render()` —— 加 `else if(S.view==='queue') renderQueue();`。
3. `DENS[view]` —— 没配会自动兜底到 `DENS.table`（`const d = DENS[S.view] || DENS.table`），
   行列默认值最好显式给一份。
4. `viewLabel()` —— 面板与读数区显示的名字。
5. i18n —— 六个语言包各加词条，缺语言的 key 会直接把 key 名显示出来。
6. `S.dens` / `S.fonts` —— 按视图记忆（切走时保存那两行已按 `S.view` 走，不用改）。

**验收**：导航页点新入口 → 两个 iframe 带 `view=queue`、标题与 tip 同步、
`← →` 提示按 `paged` 显隐、深链 `#lang=xx&view=queue` 能还原、数字键能切到。

## 十八、v2.9：A-06 综合屏（多档口混排）

### 这屏要回答什么

所有作业屏里信息量最大的一屏：**多档口的菜混在一起**，还能不能一眼读懂；以及**同一套布局怎么同时服务"可操作屏"和"只读屏"**。

### 决策点做成了屏上对照位

`KDS-原型确认清单.md` 条目 4 列了 5 个必须点头的点。我没把它们写死，而是在屏幕顶部做了一排**虚线边框的开关**：

```
布局  [网格 | 档口栏]      操作  [可操作 | 只读]      汇总  [显示 | 隐藏]
```

**虚线是有意的** —— 它表示"这是评审对照控件，不是产品功能"，交付前会删掉。这样开会时不用改代码就能当场比两种形态。

### 五个点各自的取值与理由

| # | 默认取值 | 为什么 |
|:-:|---|---|
| 1 | **8×6 网格**（48 卡/页） | 按档口分栏要新增第四种视图机制 → 动 `ActiveView` 枚举，代价**高**。默认走已有网格最省；档口栏作为**备选**留在对照位里，现场看完再决定要不要付这个代价 |
| 2 | 只读时**卡尾整条不渲染** | 置灰会被读成"坏了/没权限"。而且空出来的高度**直接换成一个数据行** —— 只读屏反而多放一屏货 |
| 3 | **每卡显示档口标签** | 多档口混排不给标签，师傅分不清这道该谁做 |
| 4 | 只读屏**只隐藏"我的划单记录"**，"换人"保留 | 划单记录点进去必然是空的；但换人在只读屏仍然有效，藏掉是错的 |
| 5 | **默认显示**顶部汇总（待制作 / 超时 / 跨日） | 综合屏常挂高处远看，纯卡片缺"总数感" |

### 自动密度调参过程

目标是让 1920×1080 **自动**吸附到清单冻结的 8×6，而不是手工钉死。理想卡从 `300×206` 一路调到 **`225×132`** 才吸附成功：

```
DENS.combo = { cols:[3..8], rows:[3..6], cw:225, ch:132, cMin:3, rMin:3 }
→ 1920×1080 验证：COLS=8 ROWS=6 CARDS=48 ✅
```

### 档口分栏模式的溢出处理

`comboCols()` 每栏封顶 `PER = 8`，超出显示 `+N` 角标。

**注意这不是偷懒**：作业屏的硬约束是「铺满整屏不滚动，超出分页」，任何一栏都不允许内部滚动。所以溢出只能**如实报告**，不能藏起来 —— 藏起来等于现场才发现第 9 道菜消失了。

### 卡结构复用

`.ccard` 直接复用单菜卡的 `.scard` 全部类名：字号系数、主题变量、`margin-top:auto` 贴底、触摸区尺寸**全部继承**，只多一个 `.cst` 档口标签。零重复产出。

### 验证结果

| 场景 | 结果 |
|---|---|
| 1920×1080 | 48 卡 = 8 列 × 6 行 ✅ |
| 只读态 | 渲染 **7 行**，卡尾节点数 = 0，"我的划单"隐藏 ✅ |
| 档口分栏 | 5 栏 ✅ |
| zh / de / ar × theme a / b（6 组） | **横向溢出 = 0，JS 报错 = none** ✅ |

## 十九、v2.10：A-12 屏端设置页

### 这屏要回答什么

行列数、字号三档、叫号、提示音、打印这些配置，**门店能不能自己改对**。

### 六个必答点怎么落的

1. **左侧五分组 + 第 6 组"数据库"**。每组标题右边标了该组条目数，避免"点了半天不知道里面有几项"。多出来的数据库组受第 5 点约束。
2. **行列数 = 输入框 + 灰色建议值**，输入失焦**也不回填**。自动改值会让师傅配的值莫名其妙被覆盖。

4. **本页是全项目唯一允许滚动的屏**，并配 ▲▼ 大按钮 —— 触控屏没有滚轮。
5. **数据库区仅 Master 显示**。给了 Master / 普通屏切换开关，切到普通屏后该组**整组消失并留一句说明**，不是置灰（置灰仍会被读成"这里也要配"）。实现靠两条 CSS：

```css
.set-grp:not(.is-master) > .set-row{display:none}
.set-grp:not(.is-master) > .set-hidden-note{display:block}
```

6. `SearchBumpWholeTable` 行右侧**红字警示**。

### 有意偏离：字号

第三册冻结项要求作业屏字号 ≥28px，**这条在设置页我没有遵守**，用了 13→20px 常规字号 + 常规行高。

理由：那条规定约束的是**站着看、1.5 米外瞄一眼**的场景。设置页是**坐下来慢慢填表**的任务，师傅会凑近看，甚至要戴老花镜逐行核 VLAN 号。此时 28px 只会让表单从一屏半翻到三屏，可读性反而更差。

> 这是**有意偏离冻结项**，已在确认清单 §4.5 标出，需要显式同意。

`updateReadout()` 原本会报告"触摸目标最小尺寸"，进到设置页时全变 0px —— 因为**那一屏还没渲染**。给它加了 `settings` 分支，改测内容盒高度、滚动余量、输入框与按钮实际高度。避免误报。

## 二十、v2.11：管理端四屏（admin.html）

### 为什么另开一个文件

作业屏是**站着戳的触控**场景（1920×1080、≥44px 触摸目标、禁止滚动）；管理端是**坐着用鼠标键鼠**的场景（1440×900、可以更密、允许滚动）。

这是**两套密度标准**。硬塞进同一个文件会让两边都别扭，也会让"作业屏必须 ≥44px"这条约束被管理端悄悄稀释掉。

> **更新（v2.13）**：管理端后来定为「鼠标为主 + 触控必须可用」—— 但**没有**因此合并回一个文件，
> 而是在 `admin.html` 内部用 `.is-touch` 换一套尺寸令牌（详见第二十三章）。
> **文件边界不变，密度可变**：办公室拿到 34px 控件，店里那台一体机拿到 46px。

### 与 v2 的继承关系

- 复用 `css/core.css` 的**全部 Token**，另建 `--adm-*` 语义别名，告别硬编码颜色；
- 所有类名 `adm-` 前缀，与作业屏零冲突；
- **零第三方库**，图表是手写 SVG（没有 Chart.js / D3）；
- 6 语言 + RTL（`dir="rtl"`），走同一套逻辑属性镜像。

### 四屏各自的冻结依据

### 无头探针——代替肉眼

## 二十三、v2.13：预览框全黑的修复 + 管理端支持触控

### 一、`index.html` 两个预览框一片漆黑 —— grid 轨道塌陷

**现象**：打开导航页，A/B 两个预览框里什么都没有，只剩上下一片深色，页头那行 `A · 夜航控制台 … 1440×900` 悬在中间。

**根因不在 iframe，在 `main` 的网格**：

```css
/* 错误写法 */
main{display:grid;grid-template-columns:1fr 1fr;align-content:center}
```

`align-content:center` 会让行轨道退化成**按内容定高**。而 `.stage` 里唯一的子元素 iframe 是
`position:absolute` —— 绝对定位元素不参与父元素撑高。于是：

```
.stage 的内容高度 = 0  →  行轨道 = 页头高度  →  .stage = 0  →  scale(0)  →  什么都看不见
```

探针实测抓住了这一条：

```
stage0=753x0  iframe=0x0  tf=matrix(0,0,0,0,0,0)   ← 高度 0，缩放 0
```

**修复**：把高度交还给网格，用 `minmax(0,1fr)` 显式声明轨道；窄屏单列时给两条轨道。

```css
main{display:grid;grid-template-columns:1fr 1fr;grid-template-rows:minmax(0,1fr);gap:16px;padding:16px 22px;min-height:0}
@media (max-width:900px){
  main{grid-template-columns:1fr;grid-template-rows:minmax(0,1fr) minmax(0,1fr)}
}
```

修好后：`stage=753x647`，iframe 按 0.523 缩放成 `753x471`，正好 1440×900 的 16:10。

> **教训**：绝对定位的 iframe + 内容定高的 grid 轨道 = 高度必定塌成 0，而且**不报错、不报警，什么都不说**。
> 只要预览框是「等下再填内容」的容器，就必须给它一个显式高度来源（`1fr` / `aspect-ratio` / 固定 px），
> 不能指望子元素撑开。这类问题用截图看只能看到「黑」，用 DOM 量 `clientHeight` 一眼就能定位。

顺手修掉一个文案口径问题：页头徽标原本写死「1920×1080 等比预览」，
切到管理端（1440×900）时会误导人以为管理端字小是压缩出来的。现在跟着入口变：

- 作业屏 → `1920×1080 等比预览`
- 管理端 → `管理端 · 1440×900`

### 二、管理端：鼠标为主，触控必须可用

**定案**：不是二选一。办公室里是鼠标键盘，店里那台一体机是手指 —— **同一个 URL 要服务两拨人**。

#### 做法：换令牌，不换样式表

管理端的尺寸本来就全部走令牌。所以只需要在 `.is-touch` 下重算 6 个值：

```css
.adm.is-touch{
  --adm-fs:15.5px;      /* 正文 14 → 15.5 */
  --adm-fs-2:14px;      /* 次要文本 13 → 14，不再有 13px 以下的字 */
  --adm-ctl:46px;       /* 控件 34 → 46，高于 44 触控下限 */
  --adm-row:48px;       /* 表格行 36 → 48 */
  --adm-nav-w:232px;    /* 侧栏 208 → 232 */
  --adm-top-h:62px;     /* 顶栏 52 → 62 */
}
```

全端几十处引用（按钮、表格行、导航项、输入框、栅格间距）**自动跟随**，
不需要第二套 `admin-touch.css`，也就不会出现"两套样式慢慢分叉、改了一边忘了另一边"。

#### 一个踩过的坑：不要用 `calc(基准 + var(--touch)*增量)`

我第一版是这么写的，想着"一个 `--touch` 管所有"。结果**字号纹丝不动**。原因：

> 自定义属性在 `:root` 上声明时，声明里的 `var()` 会在 **`:root` 这一层**就完成替换；
> 后代继承到的是**已经算死的值**（`calc(34px + 0 * 12px)`），
> 再把 `--touch` 改成 1 也不会重新计算。

探针抓到的证据：

```
TOUCH | touchvar=1 | ctl=calc(34px + 0 * 12px) | fs=14px    ← --touch 变了，令牌没变
```

所以最终写成**两套字面值**，只有 6 行，行为可预期，没有隐式求值。

#### 判定优先级

| 顺序 | 来源 | 结果 |
|:-:|---|---|
| 1 | URL `?input=touch\|mouse` | 最深链、可分享 |
| 2 | 顶栏「输入 鼠标/触控」对照位（虚线框） | 任意设备现场比对 |
| 3 | `matchMedia('(pointer:coarse)')` | 触摸一体机打开即自动进触控，不用人配 |
| 4 | 兜底 | 鼠标范式 34px |

导航页 `index.html` 会把自己的指针类型**透传**给管理端 iframe：
在触摸一体机上打开比稿页，看到的就是触控版 —— 否则会误判"管理端没法摸"。

#### 触控不只是"放大"

这几条如果不写，手指就是不好用，而且每一条都有具体后果：

| 规则 | 不写会怎样 |
|---|---|
| `min-height/min-width: 44px`（WCAG 2.5.5） | 垃圾桶图标只有 28×30，点十次中三次 |
| `touch-action: manipulation` | 每次点按多 300ms 判定"是不是双击"，感觉慢半拍 |
| `-webkit-tap-highlight-color: transparent` | 点一下留一块灰蓝方块，像脏了指印 |
| `[data-act]:active` 按压态 | 触控没有 hover，按下去没反馈 → 用户连点两次 |
| 滚动条常显 | 手指只能拖条；隐形滚动条在触控下等于"看不出还有内容" |
| `.adm-switch` 也在 44px 名单里 | 酒水 TOP 开关是 158×22 的细条，手指点不中 |

#### 验证（32 组合）

4 屏 × 2 主题 × 4 语言（zh/de/ru/ar），触控态：

| 项目 | 1440×900 | 1280×800 |
|---|:-:|:-:|
| 小于 44×44 的交互元素 | **0 个** | **0 个** |
| 文档横向溢出 | **0** | **0** |
| 顶栏横向溢出 | **0** | **0** |
| 内容区横向溢出 | **0** | **0** |
| JS 报错 | **0** | **0** |

令牌实测：鼠标态 `ctl=34 row=36 fs=14px`；触控态 `ctl=46 row=48 fs=15.5px`；
最小命中区从 `28×30` 涨到 `44×44`；来回切换可复现。

## 二十四、v2.14：登录屏重做 —— 控件居中、背景铺满、真输入

### 改了什么

原登录屏是**两栏铺满整屏**：卡的边界就是屏的边界，键盘占掉右侧三分之一的高度。
反馈后改成 **「背景铺满 / 控件居中」**：

```css
.login{
  flex:1;min-width:0;min-height:0;
  display:grid;place-items:center;
  padding:clamp(14px,2.6vh,48px) clamp(14px,3.2vw,76px);
  background:
    radial-gradient(112% 88% at 50% 36%, color-mix(in srgb, var(--brand) 9%, transparent), transparent 64%),
    var(--bg-page);
}
.login-wrap{
  display:grid;
  grid-template-columns:minmax(0,1.45fr) minmax(0,1fr);
  grid-template-rows:minmax(0,1fr);
  width:min(100%, clamp(660px, 66vw, 1180px));
  height:min(100%, clamp(440px, 68vh, 720px));
}
```

1920×1080 实测：容器 1180×670，**左右各留 334px、上下各留 101px**（`mL=334 mT=101`，两边相等即居中）。

**为什么背景必须先铺满**：控件一居中，四周就会露出来。露出来的地方如果不先铺一层有意的底，
看起来就像没做完 —— 这也是这次反馈里「背景要占满屏」的实际含义，不是加个色块就完事。

### 又踩了一次同一个坑（这次提前躲开了）

`.login-card` 是 `container-type:size`，等价于 `contain:size` —— **元素尺寸不能由内容决定**。
一旦改成「按内容定尺寸」，卡的高度会塌成 0，跟 `index.html` 预览框那个病是同一个。

所以 `.login-wrap` 的宽高必须是**确定的**（`clamp(...vw/vh)`），
并且行列显式写成 `minmax(0,1fr)`，把确定尺寸传下去，里面的 `cqw/cqh` 才有得算。

### 三条遗留一起修掉了

| 遗留 | 处理 |
|---|---|
| 登录屏没有语言入口 | 卡内加一行语言切换，6 语种**本名自称**（简体中文 / Deutsch / العربية），不给 "CN/DE/AR" 代码 —— 未登录时看不懂代码。**藏进设置里是死锁**：看不懂当前这屏的人找不到进设置的路 |
| PIN 是静态 `••••` | 点数字键真的会填：点字段切换输入目标，⌫ 退格，PIN 掩码显示；校验不过时**只标没填好的那一项**（两条一起标红，人反而不知道先改哪个），通过后给成功态再进桌台视图 |
| 工号写死 `10086` | 默认空 + 占位提示（`未输入` / `至少 4 位`），不再假装「这台机器只能这个人登」 |

### 表单状态为什么要提到模块级

`S.login = { emp, pin, tgt, err }`，**不能**写成 `renderLogin()` 里的局部变量。

因为 `render()` 每次重建整屏 —— 切语言也要重建。局部变量会在重建时被清空：
人还没输完，点了下语言，工号就飞了。探针专门验了这条，切到德语后 `emp=10086 pin=••` 原样保留。
