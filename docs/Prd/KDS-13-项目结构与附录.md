# 第十部分：项目结构

## 15. 项目结构

```
Kds.sln
├── src/
│   ├── Kds.Core/              // 领域模型、事件契约、状态机、档口匹配
│   ├── Kds.App/               // Windows 一体客户端
│   ├── Kds.Api/               // Master 内嵌服务端
│   ├── Kds.Infrastructure/    // EF Core、MQTT、SignalR
│   ├── Kds.Workflow/          // 工作流引擎（StagePath、联动判定、档口筛选）
│   ├── Kds.Printing/          // 打印子系统（模板渲染、ESC/POS 指令、任务队列、本地打印代理）
│   ├── Kds.Terminal.Maui/     // Android/iOS Worker（评估后启用）
│   └── Kds.Web/               // Web 前端（BS 终端 + 管理端）
└── tests/
    ├── Kds.Core.Tests/        // 档口匹配、StagePath、状态机单测
    ├── Kds.Workflow.Tests/    // 引擎规则与边界用例
    └── Kds.Api.Tests/         // 接口契约与幂等测试
```

**测试框架（v6.95 定案）**：

| 项 | 约定 |
|:---|:---|
| 框架 | **xUnit**（+ `Moq` 或 `NSubstitute` 做替身，+ `FluentAssertions` 做断言） |
| 命令 | `dotnet test Kds.sln -c Release`（交付必须附**原始输出**，不接受截图或摘要） |
| 覆盖率 | 新增/修改的业务逻辑必须有测试；核心模块（`Kds.Core` / `Kds.Workflow`）行覆盖率目标 **≥ 70%**（用 `coverlet` 收集） |
| 命名 | 测试类 `{被测类}Tests`，方法 `{场景}_ {预期}`；一个测试只断言一个行为 |
| 边界要求 | 状态机四条件撤销、部分划单份数、`MergeKey` 归集、档口反选、乐观锁冲突、幂等去重 —— **每类至少 1 个正向 + 1 个反向用例** |
| CI 门禁 | `dotnet build` 零警告视为通过（`TreatWarningsAsErrors` 对 `Kds.Core` / `Kds.Workflow` 生效） |

# 附录 A：术语表

| 术语 | 英文 / 枚举 | 定义 |
|------|-------------|------|
| 档口 | `Station` | 逻辑分组（非物理位置），绑定角色与品项反选规则，是品项归属的判定单位 |
| 角色屏 | `Role` | `Prep`（切配）/ `Cook`（制作）/ `Expo`（传菜），屏幕固定三类 |
| 阶段 | `WorkflowStage` | 品项流转中的一个工序位置 |
| 流转路径 | `StagePath` | 品项经过的阶段序列，如 `Prep,Cook,Expo` |
| 品项 | `DishItem` | 菜单基础资料 |
| 明细 / 菜品实例 | `OrderDetail` | 最小业务单元，划单与流转操作的对象；同品项多份 = 多条明细 |
| 份数 | `Qty` | 明细数量，支持小数 |
| 桌台 | `DiningTable` | 传菜与整桌划单的物理单位；**卡片分组键是业务键 `(OrderId, TableId)`**（不是桌台 UID，也不是关联行主键），桌号仅作展示、可随时改 |
| 无桌台 | `TableId = Guid.Empty` | 外卖 / 自提 / 外带等无实体桌位；用固定哨兵而非 NULL，业务键始终有效 |
| 订单-桌台关联 | `OrderTableRel` | **一条关联 = 一卡 = 订单在某张桌上的一份**；主键 `Uid`，业务键 `(OrderId, TableId)`（分组用业务键） |
| 联台 | — | 一个订单对应多个桌台 |
| 拼桌 | — | 多个订单对应同一桌台 |
| 划单 | Bump | 当前阶段完成并推进流转 |
| 整桌划 | — | 一次性划掉某桌台全部待制作菜品 |
| 桌台模式 | `BaseGroupMode = TableMode` | **配置页选项**：基础分组按**业务键 `(OrderId, TableId)`**，一条关联一卡，整桌划单（§3.1） |
| 订单模式 | `BaseGroupMode = OrderMode` | **配置页选项（V2）**：基础分组按**订单 UID**（`OrderId`），与桌台模式二选一 |
| 基础分组视图 | `ActiveView = BaseGroupView` | **屏幕 Tab ①**：显示桌台或订单（由 `BaseGroupMode` 决定） |
| 合菜视图 | `ActiveView = MergeMode` | **屏幕 Tab ②**：按合并条件把跨桌/跨单的同菜合成一张卡（§3.2） |
| 单菜视图 | `ActiveView = SingleMode` | **屏幕 Tab ③**：不分组不合并，每条明细一行，行内直接划单（§3.3） |
| 视图切换 | `ActiveView`（运行时） | 屏幕上三个 Tab 实时切换，不发请求、不改配置、不递增 `ConfigVersion`（§3.0.2） |
| 合并条件 | `Merge_*` | 合菜视图中决定 `MergeKey` 的 7 个开关（§2.3.2） |
| 联台组卡 | `Merge_LinkedTable` | 桌台视图把多桌订单合并成一张卡（默认关）；行内必带桌台标签（§3.1.4） |
| 流转模式 | `FlowMode` | `Auto`（自动模式，V1 实现：划单即推到下一站）/ `Manual`（手动模式，设计保留、V2 实现） |
| 广播 | `Broadcast` | 同档口多屏的**唯一**分配模式：所有屏都可见，先划者生效（§2.9） |
| 催菜 | `IsRemind` | POS 推送的催菜标记 |
| 加急 | `IsRush` | POS 推送的加急标记 |
| 等叫 | `IsHold` | 暂缓制作（计时暂停） |
| 起菜 | `IsFire` | 解除等叫，开始制作（计时恢复） |
| 沽清 | `IsSoldOut` | 品项售罄标记 |
| 退菜 | `IsCancel` | 取消该明细 |
| 赠菜 | `IsGift` | 赠送菜品，正常流转 |
| 报损 | `Void` | 菜品作废，不计入出餐 |
| 终态 | — | `Done` / `Cancelled` / `Void` |
| Revision | `Revision` | 门店级单调递增序号，任何影响屏幕展示的变更都使其 +1，用于增量同步与漏单检测（§2.10） |
| 本机轮询 | Poll | 终端定时带 `sinceRevision` 向 Master 比对版本，发现漏推即补增量；网络开销约一次整数比较（§2.10.2） |
| 推送静默看门狗 | Push Silence Watchdog | 连接"显示正常"但长时间（默认 30s）无推送时，主动触发轮询，兜住"WS 未断但推送被吞"（§2.10.2） |
| 权威数据 | Authoritative Snapshot | 来自 Master 的全量/增量结果；客户端只以它为准，不自行推断状态 |
| 离线态 | Offline | 连续轮询失败或连接断开时的界面状态：只浏览、禁提交、显示提示条（§3.6） |
| 数据滞后 | Data Stale | 超过 `DataStaleSeconds`（默认 90s）无权威数据到达，界面挂常驻提示（§2.10.2） |
