# 第一部分：PRD 产品需求文档

## 1. 产品概述

### 1.1 产品目标与定位

KDS 替代厨房纸质小票，实现订单数字化分流、多阶段制作状态可视、前后厅联动。部署在门店局域网，可对接自有 POS 以及第三方 POS，采用标准化接口推送，松耦合中心化架构。

- 服务后厨：切配、制作、传菜三角色分屏；
- 支持多语言界面，适配国内/海外门店；
- **.NET 10（LTS）/ C# 14** 开发；Win10 1809+ 可装 WPF 客户端，**Win7 只能做 Edge 109 浏览器终端**（§13.1）；
- 一套 Master 服务 + 终端 UI（Win 客户端 / 安卓浏览器 BS 终端），**终端不直连 SQL Server 数据库**；
- 门店级配置：菜品自定义流转流程、档口配置、视图配置、流转总开关；
- 一个程序多角色：小门店单机跑、大门店中心化扩展。

### 1.2 产品目标（业务）

- 独立系统，松耦合对接任意 POS；
- 三角色屏（切配/制作/传菜），品项自定义流转路径；
- 多语言界面，适配国内/海外门店；
- 一个程序多角色，小门店单机跑、大门店中心化扩展。

### 1.3 范围

| 分类 | 内容 |
|------|------|
| **V1 交付** | 事件接入、工作流引擎（三态 → 二态可降级）、分屏展示（三视图）、多语言、离线缓存与漏单自愈、门店配置后台 |
| **V1 不包含** | POS 收银、支付、会员、库存扣减 |

**V1 版本边界：**

| 项 | 说明 |
|----|------|
| 基础分组 | 仅**桌台模式**；订单模式（`OrderMode`）保留枚举与配置位，界面不开放 |
| Master 高可用 | 单 Master；故障以"数据备份 + 快速重装"恢复 |
| 总部汇总 | 保留上报接口与 Outbox 能力；跨店报表界面不做 |
| 终端形态 | Win Master + 浏览器 BS 终端；MAUI 原生客户端不在本版 |
| 前厅端 | **不做独立端**；前厅查进度由**综合屏设成只读态**（`TerminalType=Composite` + `EnableOperate=0`）承担——隐藏全部写操作入口，仅保留全景查看与检索查询（§3.5 ②③） |

### 1.5 命名统一表（全文强制）

> 同一实体只允许一个名称。**全文以下表左列为唯一合法名称**，不得使用别名。
> **命名原则：一律中性通用术语，不沿用任何具体 POS 的表名**（POS 侧可能叫 `OrderInfo` / `BaseZhuoTai` / `OrderZhuoTai` 等，均为同义别名，禁止写入本文与代码）。外部系统如何命名由适配层消化，见 §9.0。

| 统一名称（中性） | 别名（禁止使用，含 POS 侧叫法） | 说明 |
|------------------|-------------------------------|------|
| `DishItem` | `Item`、`Goods` | **品项**基础资料表（覆盖菜品、饮品、酒水、套餐子项等所有可制作/可售卖条目） |
| `OrderHeader` | `Order`、`OrderInfo` | 订单主表（一单可对应多桌） |
| `OrderDetail` | `OrderItem`、`OrderLine` | 订单明细（品项实例，最小业务单元） |
| `DiningTable` | `Table`、`BaseZhuoTai`、桌台 | 桌台主数据（物理 / 逻辑桌位） |
| `OrderTableRel` | `OrderZhuoTai`、订单桌台表 | **订单-桌台关联**：`OrderHeader 1—N OrderTableRel`、`DiningTable 1—N OrderTableRel`；**桌台视图的卡片分组键**（§9.8） |
| `TerminalConfig` | `Screen` | 终端屏幕配置表（一块屏 = 一条记录，含综合屏） |
| `TerminalId` | `ScreenUid` | 终端唯一标识 |
| `Station` | 档口、工位、站点 | 档口主配置表；逻辑分组，非物理位置 |
| `Station.IncludeTypeIds` / `ExcludeItemIds` / `IncludeItemIds` | — | 档口反选三字段：类型纳入 / 单品剔除（黑名单）/ 单品追加（白名单），见 §9.10 |
| `Workflow` | StagePath 配置、工序路径 | 品项自定义工序流程定义表 |
| `StagePath` | 工序路径 | 品项经过的阶段序列，存于 `Workflow` |
| `WorkflowStage` | `CurrentStage`、`Stage` | 流转阶段枚举字段 |
| `OperationLog` | — | 操作日志表（划单 / 状态变更 / 配置变更） |
| `EventLog` | — | 原始事件日志表（POS 入站事件全量留存，供重放与幂等） |
| `EnableOperate` | — | 终端是否允许划单（综合屏默认 false） |
| `BaseGroupMode` | — | **配置页二选一**：`TableMode`（桌台）/ `OrderMode`（订单，V2）。决定屏幕第一个视图 Tab 显示"桌台"还是"订单"（§3.0.1） |
| `ActiveView` | `ViewMode`、`DisplayMode` | **屏幕运行时三选一**：基础分组视图 / `MergeMode`（合菜）/ `SingleMode`（单菜）。实时切换、无需请求（§3.0.2） |
| 桌台 | 台位、餐桌 | 传菜与整桌划单的物理单位（主数据 `DiningTable`） |
| 卡片 / 桌台卡 | — | **一条 `OrderTableRel` 渲染成的一张卡**：订单在某张桌上的一份 |
| 划单（Bump） | 完成、打单 | 当前阶段完成动作 |
| 流转 | 工序流转 | 三态阶段推进 |
| 联动 | 自动联动、自动流转 | 阶段间是否自动推进（§1.6） |

**命名规范**：

1. JSON / DB / C# 统一 PascalCase；
2. 所有表主键统一命名 `Uid`（`uniqueidentifier`），或使用本文明确列出的业务主键名（如 `OrderHeader.OrderId`）；
3. 布尔字段以 `Is` / `Enable` / `Has` 开头（`IsGift` / `IsCancel` / `EnableOperate` / `EnableWorkflowState`）；
4. 时间字段以 `Time` / `At` 结尾，DB 统一 `datetimeoffset`，接口层 ISO 8601 带时区；
5. 枚举值统一 PascalCase 字符串（`TableMode` / `SinglePortion` / `Prep`）；
6. 配置项命名与 DB 列名严格一致（`ItemView_DetailMode` 中的下划线分组分隔符保留）。

**中文术语分层：技术用「品项」，界面用「自然语言」**

> **先承认一个事实**：`DishItem` 覆盖的不只是"菜"——可乐、酒水、套餐里的纸巾都是它。**统称"菜品"会别扭**（"菜品：可乐"），统称"品项"又不像后厨的话。所以**不强行统一成一个词，而是按使用场景分层**。

| 使用场景 | 用哪个词 | 例子 |
|----------|----------|------|
| **技术标识（英文）** | `DishItem` | `DishItem.ItemCode`（**不变**） |
| **系统术语 / 配置 / 技术文档** | **品项** | "品项基础资料""品项类型""品项级超时配置""品项匹配" |
| **后厨作业屏的**统称**文案** | **尽量不用统称**，用中性动作词 | "暂无待制作"（❌ 不写"暂无待制作菜品/品项"）、"待制作 3 项"、"超时明细"、"销量排行" |
| **界面必须出现名词时** | **菜品**（屏幕上 95% 是菜） | 空态补充说明、帮助文案 |
| **报表（产品已定文案）** | **菜品**/自然语言 | "菜品排行榜""退菜菜品""热销菜品" |
| **非菜类条目** | 直接用**具体名称** | "可乐""青岛啤酒"——界面永远显示具体名称，不显示统称 |

**判定规则（避免以后再纠结）**

```
① 界面是否在指"某一个具体东西"？
   ├─ 是 → 直接显示它的名字（可乐 / 宫保鸡丁），不用统称
   └─ 否（标题、空态、统计口径）
        ├─ 后厨作业屏 → 用动作/状态词（待制作 / 超时 / 已划单）
        └─ 报表/配置   → 用"菜品"（报表）或"品项"（配置）
② 文档、字段说明、接口描述 → 一律"品项"
```

| 常见写法对照 | 用哪个 |
|--------------|--------|
| 品项基础资料 / 品项类型 / 品项级配置 / 品项编码 | **品项**（系统术语） |
| 菜品排行榜 / 热销菜品 / 退菜菜品 | **菜品**（产品报表文案，已定） |
| 暂无待制作 / 待制作 3 项 / 超时明细 | **中性动作词**（最佳） |
| ❌ "暂无待制作菜品" / "暂无待制作品项" | 都不要，直接"暂无待制作" |

> **这不算"混用"**：`品项` 是**术语**（系统内部与配置），`菜品` 是**界面口语**（面向门店的报表文案）。类比数据库字段叫 `User`、界面上叫"会员"——同一实体在不同语境用不同称呼是正常做法，只要**边界清楚**。
> **禁止的是**：在同一个界面/同一段落里，一个地方写"品项"、另一个地方写"菜品"指同一件事。文档正文因此**统一用"品项"**，只有引述产品报表文案时才保留"菜品"。


### 1.6 关键口径（全文唯一标准）

> 以下是本系统最容易被实现错的 18 条口径。**正文任何描述与本表冲突时，以本表为准，并同步修正正文。**

| # | 议题 | 唯一口径 | 详见 |
|---|------|----------|------|
| **D1** | 档口反选判定 | `(类型命中 AND NOT 黑名单) OR (类型未命中 AND 白名单)`；**黑名单优先于白名单** | §2.2 |
| **D2** | 流转配置层级 | **两层**：① 门店总开关 `EnableWorkflowState`（是否区分工序）② 总开关开启后选**流转模式** `FlowMode` = `Auto`（**V1 实现**）/ `Manual`（**设计保留，V2 实现**）。流转触发条件**恒为"屏上划单"**，无定时推进；原第 3 层 `AutoFlowStages` 已废止 | §2.7 / §4.2 |
| **D3** | 菜品归集 | 合菜视图按**名字**（不按 UID）归类，`MergeKey` 由 **7 项合并条件**决定，**默认全开**；`规格` 恒参与且不可配 | §2.3 |
| **D4** | 关闭流转时的状态 | **双状态机**：`EnableWorkflowState=true` 走三态；`false` 走"待出 / 已划单"二态 | §2.6.3 |
| **D5** | 划单操作 | 品项到达屏幕即可直接划单，**无接单步骤**；多屏防重复靠"广播 + 实时移除 + 乐观锁" | §2.8 |
| **D6** | 同档口多屏 | 统一**广播**：所有同角色屏可见，先划者生效，其余屏实时移除该行 | §2.9 |
| **D7** | 反选数据存储 | `Station` 表三个逗号分隔字段 + 运行期内存 `HashSet` 投影；**运行期不走 SQL** | §9.10 |
| **D8** | 数据完整性 | 推送增量 + **本机轻量轮询（`Revision` 比对，默认 15s）** + 全量恢复；漏推窗口 ≤ 15s | §2.10 |
| **D9** | 视图模型 | **配置页二选一** `BaseGroupMode`（桌台 / 订单）+ **屏幕三视图实时切换** `ActiveView`（基础分组 / 合菜 / 单菜） | §3.0 |
| **D10** | 卡片分组键 | 桌台视图按**业务键 `(OrderId, TableId)`** 分组（**一条关联 = 一卡**）；订单视图按 **`OrderId`** 分组；**禁止用桌号 / 订单号 / 桌台号字符串分组**。联台（一单多桌）→ 多卡，拼桌（一桌多单）→ 多卡；**联台期间加菜订单号不变**（联台即同一订单），新增明细行按 `SourceTableId` 挂到对应桌，**不会产生额外卡片**（v6.98）；**无桌台（外卖）用 `TableId = Guid.Empty`**，外卖不联台故天然唯一。`OrderTableRel.Uid` 是行主键，**不参与分组** | §3.0.3、§3.1、§9.8 |
| **D11** | 联台组卡 | 屏幕级开关 `Merge_LinkedTable`（默认关）：开启后把**同一 `OrderId` 的多条 `OrderTableRel`** 合成一张组卡，**每行必须带桌台标签**；单桌 / 外卖订单形态不变；跨区域由 `Merge_LinkedTable_CrossArea` 控制；**联台加菜不裂卡**（同 `OrderId` 走 `Order.Update` + 新 `LineNo`，`SourceTableId` 标归属） | §3.1.4 |
| **D12** | 契约方向 | **KDS 定标准契约，POS / 第三方适配器向契约适配**；不为任何 POS 修改领域模型或契约；差异在适配器内部消化 | §9.0、§10.1 |
| **D13** | 行粒度与部分划单 | **一行 = 一个 POS `LineNo`，KDS 不合并同品项多行**（加菜必须新 `LineNo`）；划单粒度 = `DetailId + 本次份数`，`CompletedQty` 记进度，**`RemainingQty = 0` 才推进阶段** | §4.6 |
| **D14** | 部分完成与退菜回执 | **退菜仅 POS 发起**（KDS 无退菜操作，`Action=ItemCancel` 已移除），退几份由 POS 定，只能退未出品份、已出品走报损；`Item.Complete` 必带 `IsFullComplete`，POS **选择性接受**（按份记账 / 自行累计，须声明 `SupportsPartialComplete`）；**KDS 主动取消（跨日清理）才发** `Item.Cancelled`，POS 发起的退菜不回执 | §4.7 / §10.9 |
| **D15** | 分屏（V1.1） | 一屏内 2~3 栏等宽，每栏绑一组档口、**独立筛选**；**仅单菜视图**；仍是一条 `TerminalConfig`；栏间档口不重叠且并集覆盖 | §3.7 |
| **D16** | 档口语义 | `Station` = **逻辑作业分组**（非物理位置）；**5 处 `StationId(s)` 语义不同禁止混用**；`OrderDetail.CurrentStationId` 是**当前阶段**主档口、**随阶段推进重算**；多档口命中看 `MatchedStationIds`，不看单值 | §2.2.1 |
| **D17** | 套餐 | **POS 展开成子项**，`Qty` 已乘套餐份数；KDS **扁平显示 + 套餐标注**（不做三层嵌套），卡头显示套餐摘要；子项共享 `ComboNo`；不接收"套餐本体行" | §2.12 |
| **D18** | 配菜/加料 | **配菜（浇头/加料）挂在主菜上**：契约层是主菜 `OrderDetail.Toppings[]`（`ToppingId`/`Name`/`Qty`/`Unit`），**不独立成行**；KDS 入库合并为一条记录、**跟主菜一起流转**（划单/状态/出餐绑定）；POS 内部多行结构由 POS 适配器收敛。**只跟主菜**：D3 合菜归集按主菜名归集，配菜不单独归集；退配菜 = 主菜更新事件移除对应 `ToppingId` | §2.3 / §3.1–3.3 / §10.3 |
