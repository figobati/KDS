# 第十一部分：打印子系统（可选旁路）

## 16. 打印子系统

> **定位**：打印是**可完全关闭的旁路能力**——无纸化门店不配打印机即可，不影响任何主流程；有纸化门店按档口开。**打印失败绝不回滚划单**。

### 16.1 边界：V1 只出三类"划单单据"

> **V1 范围已锁定（依据门店实际票样）**：KDS **只出划单相关单据**，不出下单小票、不出结账单。是否打印由后台按档口 / 阶段配置，**默认关闭**。

| 单据类型 | V1 | 谁产生 | 说明 |
|----------|:--:|--------|------|
| 下单 / 加菜小票 | ❌ | POS | KDS 不做（重复出单） |
| 结账 / 预结单 | ❌ | POS | 财务边界 |
| **① 整桌划菜汇总单** | ✅ | KDS | 一次划单涉及**同一订单**的多道菜 → 一单一张 |
| **② 划菜汇总单（按品项）** | ✅ | KDS | 一次划单涉及**同一品项跨多个桌台** → 每品项一张 |
| **③ 划菜单（后厨档口 / 跟盘单）** | ✅ | KDS | **每道菜一张**，大字突出菜名，跟盘走 |

> 退菜单（红字作废）与催菜单属 V1.1 扩展，不在本次三张票样范围内；但**表结构与模板机制已预留**（`PrintRule.Trigger = OnItemCancel` / `OnRemind`）。

### 16.2 架构：路由层 / 通道层 / 队列层

```
┌─────────────── 路由层（打什么、从哪台出）───────────────┐
│  PrintRule：(Stage × Station) → 模板 + 触发时机 + 打印机  │
└──────────────────────────┬──────────────────────────────┘
                           ▼ 生成 PrintJob（幂等，冻结内容快照）
┌─────────────── 通道层（谁执行物理打印）────────────────┐
│  MasterDirect   ：网络打印机（TCP 9100 / Windows 队列）   │
│                    → Master 统一出单，**天然串行化**        │
│  TerminalDirect ：USB / 蓝牙打印机（就近、有距离限制）      │
│                    → 由指定的**执行终端**出单               │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────── 队列层（每个执行终端独立队列）──────────┐
│  PrintJob 落库（Status + RetryCount + 内容快照）          │
│  执行端轮询/订阅自己的队列 → 打印 → 回执更新状态           │
└────────────────────────────────────────────────────────┘
```

**三种连接方式的取舍（这是你问的技术前提）**

| 连接方式 | 交给谁执行 | 优点 | 限制 |
|----------|-----------|------|------|
| **网络打印机**（Ethernet/WiFi，ESC/POS over TCP 9100） | **Master** | 单队列串行化、状态集中监控、断网可排队 | 打印机需在后厨网内；Master 需能路由到该 IP |
| **USB 打印机** | **终端**（本机） | 就近出纸、便宜 | 只能由插着它的那台终端打；该终端关机即无法出单 |
| **蓝牙打印机** | **终端**（本机） | 无线、位置灵活 | **有距离限制**；**浏览器终端不支持蓝牙**（需原生客户端或本地打印代理） |

> ⚠️ **浏览器终端的硬限制**：纯 BS 终端（Win7 / 安卓浏览器）无法直接驱 USB 或蓝牙打印机。若门店用这类终端出单，必须二选一：① 该单据改由**网络打印机**经 Master 出；② 在该机位部署**本地打印代理**（小服务/原生壳）。这一点必须在上门实施前确认，否则现场无法交付。

### 16.3 打印机绑定：**关联档口还是关联屏？——两者都不是二选一**

**结论：路由按"档口"，执行按"通道"，打印机既可以绑档口也可以绑屏。**

| 层 | 绑定对象 | 为什么 |
|----|----------|--------|
| **路由**（哪些单从这台机出） | **档口（`Station`）+ 阶段** | 单据的产出对象是"工序"而不是"显示器"。绑档口才能保证**同一道菜同一阶段只出一次单** |
| **执行**（谁驱动它） | 网络机 → **Master**；本地机 → **指定终端** | 由物理连接方式决定，不由业务决定 |

**为什么不能只绑"屏"**：同一档口常挂多块屏（广播模式）。若打印机绑屏，同一道菜会被每块屏各打一张 → **重复出单**，而后厨无法分辨"这是第二份菜还是重复单据"。所以路由必须收敛在档口。

**那"每块屏个性化打印"怎么实现？** 通过给不同终端各配一台 `TerminalDirect` 打印机：想打的那块屏配、不想打的不配。**个性化落在"有没有打印机"，而不是"同一条路由被多台机重复执行"。**

**去重规则（必须写死）**：一个 `PrintJob` 只由一个执行者消费，选定顺序：

```
1. 该 (Stage, Station) 存在启用的 MasterDirect 打印机 → Master 执行（唯一，天然不重复）
2. 否则存在启用的 TerminalDirect 打印机且其执行终端在线 →
   选「同档口绑定终端中 PrintPriority 最高（默认 TerminalId 升序最先）」的那一台
3. 否则 → 任务保持 Pending，屏幕告警"打印机离线"，支持人工补打
```

> 明确**不做**"多台同时出同一张单"（除非门店显式配置"双联打印"，这属于 V2 的 `PrintRule.Copies`）。

### 16.4 触发时机与模板类型

**触发时机（`PrintRule.Trigger`，档口级可配）**

| 取值 | 时机 | 典型用途 |
|------|------|----------|
| `OnStageEnter` | 品项进入该阶段 | 切配工单、打荷单 |
| **`OnStageComplete`** | **该阶段划单完成** | **跟盘单（中餐主场景）** |
| `OnOrderDone` | 整单完成 | 整桌核对单 |
| `OnItemCancel` | 退菜 / 作废 | 红字作废单 |
| `OnRemind` | 催菜 / 加急 | 加急标单 |
| `None` | 不打 | 无纸化 / 该档口不出单 |

**模板类型（`PrintTemplate.TemplateKind`）—— 对应门店真实票样**

| 类型 | 名称 | 聚合粒度 | 一次划单出几张 | 票样 |
|------|------|----------|----------------|------|
| **`OrderSummary`** | 整桌划菜汇总单 | **1 个订单**（+桌台） | 1 张 | 票样① |
| **`ItemSummary`** | 划菜汇总单（按品项） | **1 个品项**（跨桌台聚合） | 每品项 1 张 | 票样② |
| **`ItemSlip`** | 划菜单（后厨档口 / 跟盘单） | **1 条明细** | 每道菜 1 张 | 票样③ |

> **聚合粒度是模板属性，不是触发点属性**。同样是"整桌划"：用 `OrderSummary` 出 1 张、用 `ItemSlip` 出 N 张（N = 菜数）、用 `ItemSummary` 出 M 张（M = 品项数）。这决定了**批量划单时的拆单逻辑**：

```
一次划单请求（单条 / 选中多条 / 整桌划）涉及明细集合 S
  ├─ 模板 ItemSlip     → 对 S 中每条明细各生成 1 个 PrintJob
  ├─ 模板 OrderSummary → 按 OrderId 分组，每组 1 个 PrintJob
  └─ 模板 ItemSummary  → 按 品项聚合键（§2.3.3 MergeKey）分组，每组 1 个 PrintJob
```

> 三类模板都要支持**多语言**（方案见 §16.5「多语言模板」）：模板**语言无关**，静态文本走语言包 key；品项名/口味等变量值在上游已解析为单语言字符串（§11.2），模板不参与翻译。

### 16.4.1 三张票样的字段与版式（以门店实票为基线）

**票样① 整桌划菜汇总单（`OrderSummary`）**

```
          整桌划菜汇总单
       桌台: 思乐vip19
- - - - - - - - - - - - - - - -
订单号: 202610211110400001
菜品                    单位   数量
- - - - - - - - - - - - - - - -
黑胡椒牛肉粒              份     1
-加一点辣椒炒                      ← 做法/备注缩进一行（续行）
莴苣炒蛋                  份     1
鲜麻青椒牛油锅底附毛肚鸭肠黄   份     1   ← 超长自动折行
- - - - - - - - - - - - - - - -
              合计品项: 3 个
     打印时间: 2026-10-21 11:12:38
```

| 要点 | 规格 |
|------|------|
| 标题 | 居中、字号略大 |
| 桌台行 | `桌台: {TableName}`（**优先桌台名**，无则用 `TableCode`） |
| 订单号行 | 左对齐，`订单号: {PosOrderNo}` |
| 表头 | `菜品 / 单位 / 数量` 三列；数量右对齐 |
| 菜名 | 超宽**自动折行**（不是截断）；做法/口味以 `-{Taste}` 缩进**续行**显示，不占独立列 |
| 合计 | `合计品项: {N} 个` 居中；**N = 本次划单涉及明细行数**（不是份数之和） |
| 尾部 | `打印时间: {PrintTime}` 居中 |

**票样② 划菜汇总单 · 按品项（`ItemSummary`）**

```
            划菜汇总单
          品项: 黄焖鸡 (5)          ← 品项名 + 总份数
- - - - - - - - - - - - - - - -
桌台        做法        单位    数量
- - - - - - - - - - - - - - - -
A88         微辣        份       3
C1          不辣        份       2
- - - - - - - - - - - - - - - -
              合计品项: 1 个
     打印时间: 2026-10-21 11:21:41
```

> 上例为「做法独立成列」的排法（票样原样，该品项恰好无做法所以列为空）。**做法还有"独立成行"的排法**，见 §16.4.2——中餐菜名普遍较长，成行排法更容易读。

| 要点 | 规格 |
|------|------|
| 标题行 | `品项: {DishName} ({总份数})` —— 总份数 = 该品项本次划单的 `Qty` 之和；**标题超宽时居中折行**，不截断 |
| 四列 | `桌台 / 做法 / 单位 / 数量`；做法为空时**保留空列**（对齐不乱）——或改用 §16.4.2 的成行排法 |
| 按桌台展开 | 每个涉及桌台一行（同一桌台多条明细时按 `Qty` 合并） |
| 合计 | `合计品项: N 个`；**N = 涉及品项数**（本模板恒为 1，但保留字段以便模板复用） |

**票样③ 划菜单 · 后厨档口 / 跟盘单（`ItemSlip`）**

```
        划菜单(后厨档口)
2026-10-21 11:14:42
送单人: kkn
订单号: 2026102111105500002

      鸟语花香桌              ← 大字号（桌台名）
  黑胡椒牛肉粒(加一点辣椒炒)     ← 最大字号（菜名 + 做法内联）
                          ← 空行留白
         数量:1份            ← 中字号
```

| 要点 | 规格 |
|------|------|
| 抬头 | `划菜单({档口名})` 居中，小字号 |
| 元信息 | 时间 / `送单人: {OperatorName}` / `订单号`，左对齐小字号 |
| **桌台名** | **大字号居中**（约 2× 正文） |
| **菜名** | **最大字号居中**（约 2.5~3× 正文），做法以**全角括号内联**：`{DishName}({Taste})` |
| 数量 | `数量:{Qty}{Unit}` 居中，中字号 |
| 留白 | 菜名与数量之间保留空行，便于对盘时快速扫读 |
| 折行 | 长菜名按宽度折行，**居中逐行** |

> **为什么票样③ 必须大字号**：这张单是**跟着盘子走**的，传菜员在嘈杂后厨要一眼看清"这盘菜是哪桌的、点了什么"。小字号排版在这一场景下不可用——这也是为什么**推荐 `Bitmap` 软字体渲染模式**（字号自由，见 §16.5）。

### 16.4.2 版式与折行规则（三类模板共用，必须按此实现）

> **问题的根源**：中餐菜名、做法普遍较长（`鲜麻青椒牛油锅底附毛肚鸭肠黄喉`、`黑胡椒牛肉粒(加一点辣椒炒)`）。如果强行按"菜名 | 做法 | 单位 | 数量"四列排，58mm 纸只有 32 字符宽，菜名会被压到 8~10 字，**几乎必然挤成一团**。所以必须有明确的折行规则，而不是让渲染器自己挤。

**A. 主文本列放不下时：名称独占一行，其余列另起一行**

```
【正常】菜名放得下                       【超宽】菜名放不下
--------------------------------      --------------------------------
菜品              单位   数量          莴苣炒蛋                份     2
莴苣炒蛋           份     2            --------------------------------
                                      鲜麻青椒牛油锅底附毛肚鸭肠黄喉
                                                  份      1        ← 其余列另起一行
```

**折行判定算法（实现口径）**

```
1. 按纸张宽度算「可用字符宽」：58mm → 32；76mm → 40；80mm → 48（GBK 半角口径，中文占 2）
2. 预留固定列宽：单位 4、数量 6、列间隔 2 → 主文本可用宽 = 32 - 4 - 6 - 2 = 20
3. 对每条明细：
   if 显示宽度(菜名) ≤ 主文本可用宽:
        单行排列：菜名 | 单位 | 数量（数量右对齐）
   else:
        菜名独占一行（整行左对齐，不截断）
        次行排列：单位 | 数量（按列对齐到原表头位置）
4. 做法（Taste/Method）按 B 节规则处理，不占主文本列
```

**B. 做法的三种排法（`PrintTemplate.TasteLayout`，模板级可配）**

| 取值 | 排法 | 示例 | 推荐场景 |
|------|------|------|----------|
| **`OwnLine`（默认）** | **独立成行**，缩进 2 空格 + `-` 前缀 | `黑胡椒牛肉粒`<br>`  -加一点辣椒炒` | **汇总类单据**（票样①②）：菜名与做法都长时最清晰，不会把列挤乱 |
| `Column` | 独立一列（票样② 原样） | `A88 | 微辣 | 份 | 3` | 做法普遍很短的门店；做法为空时该列为空 |
| `Inline` | 全角括号内联在菜名后 | `黑胡椒牛肉粒(加一点辣椒炒)` | **跟盘单**（票样③）：单菜单张，不需要列对齐，内联最省空间 |

> **默认 `OwnLine`**：门店票样②里做法列是空的（那品项本身没有做法），一旦有做法且菜名也长，`Column` 排法就会挤；`OwnLine` 在长短混合时最稳。

**C. 列宽基线（58mm / 32 字符）**

| 模板 | 列 | 宽 | 对齐 |
|------|----|:--:|------|
| `OrderSummary` | 菜品 | **20**（弹性，超宽走 A 规则） | 左 |
| | 单位 | 4 | 居中 |
| | 数量 | 6 | **右对齐** |
| `ItemSummary` | 桌台 | 8（弹性） | 左 |
| | 做法 | 10（`TasteLayout=Column` 时占位；`OwnLine` 时并入次行） | 左 |
| | 单位 | 4 | 居中 |
| | 数量 | 6 | **右对齐** |

> 80mm 纸（48 字符）：主文本列宽按比例放大（菜品 32 / 桌台 12 / 做法 16），其余列宽不变。

**D. 其他一律遵守的排版约定**

| 项 | 规则 |
|----|------|
| **不截断** | 任何名称、做法、备注都**折行而不是省略号截断**（单据是给人核对用的，截断等于信息丢失） |
| **对齐** | 数量列**恒右对齐**（便于一眼比对份数）；单位列居中；文本列左对齐 |
| **续行缩进** | 折行后的续行缩进 2 空格，与首行区隔 |
| **明细间隔** | 默认不加空行（省纸）；`OrderSummary` 在"菜名换行"的明细之间加 1 空格行，避免上下两条粘在一起 |
| **标题** | 居中；超宽居中折行 |
| **分隔线** | 用 `- ` 重复（虚线感），宽度 = 纸宽；不用实线字符（部分字库缺字） |
| **空值** | 做法/备注为空时**不输出该行**（`OwnLine` 模式）或**保留空列**（`Column` 模式），不留空行 |

**E. 长文本样例（验收用）**

```
            整桌划菜汇总单
         桌台: 思乐vip19
- - - - - - - - - - - - - - - -
订单号: 202610211110400001

- - - - - - - - - - - - - - - -
黑胡椒牛肉粒              份     1
  -加一点辣椒炒
莴苣炒蛋                  份     1
鲜麻青椒牛油锅底附毛肚鸭肠黄喉
                          份     1
- - - - - - - - - - - - - - - -
              合计品项: 3 个
     打印时间: 2026-10-21 11:12:38
```

> 上例三处都验证了规则：① 做法 `OwnLine` 续行缩进；② 超长菜名独占一行、单位/数量另起一行；③ 全部内容无截断。


### 16.5 单据排版方案（软字体 + 模板树）

**推荐：一套模板定义，两种渲染模式（`RenderMode`）**

| 模式 | 产物 | 适用 | 优点 | 代价 |
|------|------|------|------|------|
| **`Bitmap`（软字体位图）** | 单色位图（`GS v 0`） | 多语言混排 / 复杂排版 / 有 LOGO | **所见即所得**，不依赖打印机字库，纯 C# 渲染 | 传输量大（58mm 单张约 10~30KB）；打印慢 |
| **`EscPos`** | ESC/POS 指令流 | 标准热敏机（58/80mm）、低端机 | 传输小、速度快、原生条码 | 排版受限；中文需 GB18030；跨型号指令差异 |

**被否决的备选：无头浏览器 HTML 渲染**

> 原方案（§16.5 初稿）是「HTML+CSS 模板 → 无头浏览器渲染成位图」。过程：模板写成受限 HTML/CSS → 渲染时启动一个无头浏览器内核（Chromium / WebView2，无界面）→ 内核加载 HTML 做布局（layout）+ 光栅化（rasterize）→ 截取单色位图 → `GS v 0` 输出。
> **否决理由**：无头浏览器是重依赖——随 Master 带一个数百 MB 的内核、常驻内存、启动慢，工控机（4 核 8G）高峰密集出单时渲染吞吐扛不住；打印小票的排版需求远低于 Web 页面，用浏览器内核是「杀鸡用牛刀」。

**定稿：软字体 + 模板树渲染（`Bitmap` 模式）**

```
模板 = 结构化模板树（节点 + 样式，非 HTML）
        │
        ├─ RenderMode = Bitmap  → 纯 C# 渲染器（System.Drawing / SkiaSharp）
        │                         遍历模板树，用内嵌软字体（打包 TTF）画单色位图
        │                         → GS v 0 输出（不依赖无头浏览器、不依赖打印机字库）
        └─ RenderMode = EscPos  → 模板树里的语义块映射为指令
                                  （标题/大字号/居中/分隔线/表格/条码）
                                  只支持"语义子集"，复杂排版提示降级
```

**为什么这么选**：

1. **工控机友好**：纯 C# 绘制，无浏览器内核依赖，内存/CPU 占用小、启动快，高峰密集出单不成为瓶颈；
2. **多语言**：软字体（内嵌 TTF）渲染，不依赖打印机字库，中/英/繁/日/泰混排不乱码；
3. **排版可控**：字体度量（`SoftFontMetrics`）、折行（`TextWidthSplitter`）、对齐全部自实现，行为确定、可单测；
4. **兼容性兜底**：老机型只吃 ESC/POS 时降级到语义子集，保证"能出一张能看的单"；
5. **预览即真实**：预览渲染器与打印渲染器**共用同一套「模板树 → 位图」逻辑**，所见即所打（预览细节见 §16.7）。

> **代价（如实记录）**：模板表达力弱于 HTML/CSS（不支持浮动/渐变等 Web 特性，但打印小票本就不需要）；模板需结构化（模板树），不能直接写 HTML/CSS。

**字号枚举（`EscPos` 语义子集 + `Bitmap` 软字体共用，13 档）**

| 枚举值 | 含义 | 宽度因子 | 高度因子 |
|:------:|------|:--------:|:--------:|
| 0 | 正常 | 1 | 1 |
| 1 | 两倍高 | 1 | 2 |
| 2 | 两倍宽 | 2 | 1 |
| 3 | 两倍大 | 2 | 2 |
| 4 | 三倍高 | 1 | 3 |
| 5 | 三倍宽 | 3 | 1 |
| 6 | 三倍大 | 3 | 3 |
| 7 | 四倍高 | 1 | 4 |
| 8 | 四倍宽 | 4 | 1 |
| 9 | 四倍大 | 4 | 4 |
| 10 | 五倍高 | 1 | 5 |
| 11 | 五倍宽 | 5 | 1 |
| 12 | 五倍大 | 5 | 5 |

> 票样③ 跟盘单的「菜名最大字号」对应 `size=6`（三倍大），「桌台名大字号」对应 `size=3`（两倍大）。

**软字体渲染两条硬约定（来自老系统 previewDanJu.js 实战）**：

1. **多字号混排底边对齐**：同一物理行内不同字号的字符，**底边（baseline）对齐**——真实热敏机逐段打印时各段字符基底对齐；渲染器缩放锚点必须取底边（不是顶边），否则大字号段会顶部对齐、底部错开。
2. **浮点宽度收敛**：软字体宽度是浮点数，折行判定「刚好满宽」会因浮点误差误判；宽度计算统一收敛到 3 位小数再比较。

**多语言模板（方案 C：模板语言无关，静态文本走语言包）**

> 语言会持续扩展（不止 zh-CN / en-US / zh-TW，未来日 / 泰等），因此**不做「按语言各存一份模板」**（会随语言数量爆炸）。模板永远只有 3 份（3 类票样），**不绑定语言**。

| 点 | 规则 |
|----|------|
| **静态文本** | 存语言包 key（`print.orderSummary.title` / `print.table.label` / `print.header.dish` 等），归入 §11 语言包 `print.*` 命名空间 |
| **变量值** | 上游已解析单语言字符串（§11.2），模板不碰翻译 |
| **渲染选语言** | 按屏 `TerminalConfig.CurrentLang`（或档口默认语言）从语言包取 key 翻译 + 变量值 → 软字体渲染 |
| **加语言** | 只在 `docs/Design/lang/` 加一份 json（如 `ja-JP.json`），模板与渲染逻辑**零改动** |
| **缺 key 回退** | 某语言缺 key → 回退基准 zh-CN → 告警（对齐 §11.7 语言包完整性自检，**绝不打空白/key**） |
| **软字体字形** | 内嵌 TTF 按需增量补字形（加日文补假名、加泰文补泰字形），字体文件可扩展；SC/TC 不互顶替（§11.6） |
| **EscPos 边界** | GB18030 罩不住日/泰等字形 → **多语言门店锁死 Bitmap 软字体模式**，EscPos 仅纯中文店 |

### 16.6 队列与可靠性

**每个执行终端一条独立队列，全部落库。**

`PrintJob` 状态机：

```
Pending ──claim──► Printing ──ok──► Success
   │                   │
   │                   └──fail──► Failed ──retry──► Pending（RetryCount+1）
   │                                     └─超过上限──► DeadLetter（人工补打）
   └──cancel（退单/已重打/超时）──► Cancelled
```

| 机制 | 规则 |
|------|------|
| 幂等键 | `DetailId + Stage + TriggerType + PrintIndex=1`。同一菜同一阶段同一触发**只自动打一次** |
| 投递语义 | **至少一次**（宁可重复不可漏打），重复由"第 N 次打印"标识 + 打印记录核对 |
| 执行端拉取 | `GET /api/Print/Jobs?terminalId=&max=10` 领取任务（原子 claim，带租约，超时自动回收） |
| 回执 | `POST /api/Print/Jobs/{jobId}/Result`（`Success` / `Failed` + 错误码 + 打印耗时） |
| 串行化 | **同一台打印机同一时刻只允许一个任务**（Master 侧按 `PrinterId` 串行；终端侧单线程队列）；**网络打印机按 IP 聚合队列**——同一 IP 的多条配置共享一个队列，避免并发写 Socket 乱序 |
| 优先级 | `Cancel`（退菜单） > `Complete`（跟盘单） > `Remind` > 其他；同级 FIFO |
| 断网 | 终端本地队列继续打印（网络机不可用则挂起），恢复后与 Master 对账（按 `JobId` 幂等） |
| 不阻塞 | 划单事务提交后**异步**生成任务；打印失败不回滚划单 |
| 快照 | 任务生成时冻结渲染内容与模板版本，**补打不重新渲染**（除非人工选"按当前数据重渲"） |
| 清空队列 | `ClearPrintQueue` **记一个时间点**，不直接清队列；消费时 `CreatedAt` 早于清空时间点的任务丢弃并记「中止打印」（避免清空动作与在途任务竞态） |
| 备打切换 | 主打印机失败 + 超过 1 分钟 + 配置了 `FallbackPrinterId` 且备打可用 → 切到备打打印机继续出单，单据头部打提示语；`LastPrinterId` 记录实际执行的打印机 |
| 分块发送 | 二维码/图片等大字节载荷（`GS v 0` 位图 10~30KB）**分块发送**，避免一次写超长丢包（蓝牙/串口尤其） |

### 16.7 管理端：配置、记录、预览、自检

| 页面 | 内容 |
|------|------|
| **打印机配置** | 新增/编辑打印机：`PrinterName`、型号、`ConnectionType`（`Network` / `Usb` / `Bluetooth`）、IP+端口（网络）或执行终端（本地）、`PaperWidth`（58/76/80）、`Encoding`、`RenderMode`（`Bitmap` / `EscPos`）、`IsEnabled`、`FallbackPrinterId`（备打，可选） |
| **打印规则** | 按（阶段 × 档口）配：是否打印、模板、触发时机、执行打印机、份数（V2） |
| **模板管理** | 模板列表（`OrderSummary` / `ItemSummary` / `ItemSlip`，**语言无关、不按语言分份**）、**模板树编辑**、变量插入、**实时预览（软字体位图渲染，与打印共用同一渲染器）**、试打 |
| **打印记录（可反查）** | 见下方「打印记录闭环」 |
| **补打** | 记录行 → 补打（新 `PrintIndex`），需权限 |
| **自检** | ① 打印机连通性（TCP 连接 / 队列存在 / 纸张宽度与编码校验）；② 测试页打印（含中文样张）；③ 队列积压与 DeadLetter 告警；④ 打印规则覆盖检查（哪些档口开了打印但没有打印机 / 打印机无执行终端） |

**打印记录闭环（`PrintJob` 即记录，可反查）**

> `PrintJob` 表同时承担「执行队列」与「打印记录」两个职责——**入队即落记录，全程状态可反查**。

| 环节 | 规则 |
|------|------|
| **入队落记录** | 生成 `PrintJob` 时写入：内容快照 `ContentSnapshot`、目标打印机 `PrinterId`、触发来源（`DetailId` + `Stage` + `TriggerType`）、`PrintIndex`、`CreatedAt` |
| **状态多次更新** | 状态机：`Pending` → `Printing` → `Success` / `Failed` / `Cancelled` / `DeadLetter`；每次状态变更更新 `PrintCount`（重试次数）、`LastPrinterId`（实际执行打印机）、`ErrorCode`、`FinishedAt` |
| **主动恢复** | 营业日开始后（或 Master 重启后），查询「未完成且未中止」的记录（`Pending` / `Failed` 未超上限）重新入队，兜住打印中断 |
| **补打可溯源** | 补打生成新 `PrintJob`（`PrintIndex+1`），沿用原 `ContentSnapshot`（**不重新渲染**，除非人工选「按当前数据重渲」）；新旧记录通过 `SourceJobId` 关联，可查完整补打链 |
| **保留期** | 打印记录保留期 **60 天**；`Success` 记录 60 天后清理，`Failed` / `DeadLetter` 保留至人工处置（不自动删） |
| **反查入口** | 列表按 时间 / 桌号 / 品项 / 打印机 / 执行终端 / 状态 / `PrintIndex` 筛选；详情含内容快照、状态流转时间线、错误信息、补打链 |

**模板自定义编辑器（V1.1）**

> 参考老系统 `Setup/Print` 可视化设计器，但**砍掉自由拖拽**，收窄为「固定骨架 + 字段/样式自定义」。

- **固定骨架**：3 类票样 = 3 个固定模板，结构写死（票样①三列 / ②四列 / ③大字跟盘单），用户不改结构
- **可改的**：字段显隐、字号、对齐、是否打印做法、折行排法（`OwnLine` / `Column` / `Inline`）、静态文本的语言包 key 绑定
- **布局简化**：字段选择（勾选）→ 预览（软字体位图，所见即所得）→ 属性面板
- **行宽超限实时校验**：对应 §16.4.2 折行判定，超限红字阻断保存
- **语言切换**：编辑器顶部语言 tab，切换只改预览解析语言；**加语言不进编辑器**（走语言包，§16.5 方案 C）
- **不做**：自由拖拽、分组/表格元素、字段使用统计、导入导出（后两项视需求进 V2）

**自检项（与 §2.11 路由自检同级，建议同一"健康检查"页）**

| 检查项 | 严重度 | 后果 |
|--------|:------:|------|
| `PRINTER_UNREACHABLE` 打印机 TCP 不通 | 高 | 出不了单 |
| `PRINTER_NO_EXECUTOR` 本地机未指定执行终端 / 终端离线 | 高 | 该机位不出单 |
| `RULE_WITHOUT_PRINTER` 档口开了打印但无可用打印机 | 高 | 静默不出单 |
| `TEMPLATE_RENDER_FAIL` 模板渲染异常 | 高 | 打空白/报错 |
| `ENCODING_MISMATCH` 中文进 UTF-8 模式 | 中 | 乱码 |
| `QUEUE_BACKLOG` 队列积压 > 50 | 中 | 出单延迟 |
| `DEAD_LETTER` 存在终态失败任务 | 中 | 需人工补打 |

### 16.9 边界与风险

| 风险 | 缓解 |
|------|------|
| 与 POS 下单小票重复 | 定位收窄（只做完成单 / 退菜单 / 催菜单），实施前确认门店现有打单流程 |
| 打印机型号碎片化 | **V1 锁定 ESC/POS over TCP 9100 + 指定热敏型号清单**；非清单型号不承诺 |
| 浏览器终端不能驱 USB/蓝牙 | 实施前按机位确认：改网络机经 Master，或该机位部署本地打印代理 |
| 中文乱码 | 强制 `GB18030`；模板自检做"中文样张"试打 |
| 西文扩展字符 | `€` 等符号部分机型需 `ESC t n` 切 codepage 或特殊字节映射；编码探测不盲用默认，按机型确认 |
| 重复出单（以为加菜） | 幂等键 + "第 N 次打印" + 打印记录可查 |
| 漏打（菜没单跟盘） | 至少一次投递 + 屏幕告警 + 补打入口 + `DEAD_LETTER` 每日巡检 |
| 打印拖慢出餐 | 异步队列、不阻塞划单；打印失败不回滚 |

### 16.10 版本切分建议

| 版本 | 范围 | 估时 |
|------|------|------|
| **V1 最小** | 网络打印机（TCP 9100，Master 直出）+ `OnStageComplete` + 单菜/多菜两模板 + `Bitmap` 软字体渲染 + 记录/补打/自检 + 预览 | 8~11 人日 |
| V1.1 | **模板自定义编辑器（简化版：固定骨架 + 字段/样式，多语言走语言包 key）** + `EscPos` 原生指令模式（速度优化）+ 终端本地 USB 打印代理（Windows 服务） | +10~14 人日 |
| V2 | 蓝牙（原生端）、份数/双联、标签打印（TSPL）、模板导入/导出 | +8~12 人日 |

> **建议**：V1 先做**网络机 + 软字体渲染（Bitmap）**这条路——它同时解决"多语言不乱码"和"门店个性化排版"，且不需要终端驱动能力；本地 USB/蓝牙留给 V1.1，等确认门店机位与终端形态后再投。
