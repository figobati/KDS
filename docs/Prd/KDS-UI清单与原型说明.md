### 1.5 显示模式（**不是"主题"，是三种环境适配 + 6 个可调槽位**）

> **结论先给**：**不做"浅色/深色两套主题"，也不做"完全可扩展主题系统"**。
> 走中间路线：**3 个内置显示模式 + 6 个可配置语义槽位**，且**每块屏独立选**（不是全店统一）。

**为什么不是两套主题**

| 两套硬编码（Light/Dark） | 问题 |
|---|---|
| 光照只有"亮/暗"两种假设 | 实际至少三种：**明亮后厨**（灶台灯）、**暗厨房/夜宵**（只有备餐灯）、**强反光区**（油烟糊屏、老屏、师傅老花眼）——第三种不是"暗"，是**需要更高对比**，换深色底解决不了 |
| 每加一个组件画两遍 | 38 个屏 × 2 = 76 张，维护成本翻倍 |

**为什么不是完全可扩展主题**

| 让门店自由配色 | 后果 |
|---|---|
| 状态色可改 | **红色不再表示超时** → 师傅看错 → **出餐出错**。状态色是**安全信息**，不是品牌装饰 |
| 字号可改 | 改小到 20px → 1.5 米外看不清 → 天天漏单 |
| 结果 | 变成"内部设计平台"，只有实施会用，配错了还查不出来 |

### 1.5.1 三个内置显示模式

| 模式 | 适用环境 | 页面底 | 卡片底 | 正文 | 对比度 |
|------|----------|--------|--------|------|:------:|
| **标准（默认）** | 明亮后厨 | `#F5F6F7` | `#FFFFFF` | `#1F2329` | 4.5:1 |
| **强对比** | 强反光 / 油烟 / 老屏 / 远距离 / 师傅老花 | `#FFFFFF` | `#FFFFFF` | **`#000000` + 字重 +1** | **7:1** |
| **暗环境** | 夜宵 / 暗厨房 / 传菜口暗区 | **`#14161A`** | `#1F2329` | `#E8EAED` | 4.5:1 |

> **暗环境不用纯黑 `#000`**：LCD 上纯黑 + 白字会产生**光晕（halation）**，长时间看更累。用近黑 `#14161A` / `#1F2329` 更稳。
> **默认是"标准"而不是"暗环境"**：后厨主流是亮环境，默认给深色会让 90% 的门店第一眼"看不清"。

**每块屏独立选的原因**

同一家店里，**灶台区亮、传菜口暗**。把显示模式做成"门店全局设置"必然一边不合适。所以它落在 `TerminalConfig` 上，不是 `StoreConfig`。

### 1.5.2 只开放 6 个语义槽位

| 槽位 | 能否改 | 约束 |
|------|:------:|------|
| `bg-page`（页面底） | ✅ | 明度受限（太暗自动拒绝） |
| `bg-surface`（卡片底） | ✅ | 与 `bg-page` 明度差 ≥ 8% |
| `text-primary` | ✅ | 与卡片底对比度**自动校验 ≥ 4.5:1**，不达标拒绝保存 |
| `brand-primary`（品牌色/高亮） | ✅ | 仅用于选中态、主按钮；**不得用于状态色** |
| `density`（宽松/紧凑） | ✅ | 紧凑只缩间距，**行高不得低于 56px** |
| `status-*`（6 个状态色） | ❌ **不可改** | 只允许切换"色盲友好强化"（加图案/边框样式） |
| 字号 / 触摸尺寸 / 布局 / 动效 | ❌ **不可改** | **安全下限，不是偏好** |

### 1.5.3 状态不只靠颜色（色盲与强反光双保险）

| 状态 | 颜色 | **第二重标识**（必做） |
|------|------|----------------------|
| 超时 | 红 | 左侧实心色条 + **徽标文字"超时"** |
| 预警 | 黄 | 左侧实心色条 + 徽标"将超时" |
| 催菜 | 橙闪 | 徽标"催" + 闪烁 |
| 等叫 | 灰 | 整卡降饱和 + 徽标"等叫" |
| 退菜 | 红 | **删除线** + 徽标"退" |
| 跨日 | 红 | 徽标"跨日 N 天" + **置顶** |
| 沽清 | 黄 | 徽标"已沽清" |
| 完成 | 绿 | 绿勾 + 时长定格 |

> **`color-blind` 强化模式**（可选开关）：把"红/绿"对替换为"红/蓝"对，并给超时加**斜纹底**、预警加**虚线边**。约 **8% 男性**有红绿色觉异常，后厨男性比例极高，这不是过度设计。

### 1.5.4 实现方式（Token 三层，切换只换变量）

```
① 原子层 Primitive   gray-50..900 / red-500 / amber-500 …（不直接用）
② 语义层 Semantic    --kds-bg-surface / --kds-text-primary / --kds-status-timeout …
③ 组件层 Component   .card{background:var(--kds-bg-surface)}
```

| 要求 | 说明 |
|------|------|
| 切换方式 | `:root` 注入 CSS 变量，**组件代码零改动** |
| 存储 | `TerminalConfig` 存 `DisplayMode` + `ThemeOverrides`(JSON，只含 6 个槽位) |
| 保存校验 | 改 `text-primary` 时**实时算对比度**，< 4.5:1 拒绝并提示 |
| 预览 | 配置页右侧给"当前模式 + 本机样式"的小样预览 |
| 管理端 | **只有"标准/强对比"两档**（办公室环境不需要暗环境） |

**哪些"客户诉求"要拒绝**

| 诉求 | 处置 |
|------|------|
| "用我们的品牌红做主色" | ✅ 允许改 `brand-primary`；❌ **不允许改 `status-timeout`** |
| "字号再小一点，能多显示几行" | ❌ 拒绝。要更多行请用**紧凑密度**（只缩间距） |
| "全都改成深色" | ⚠️ 允许，但**先让客户在真实工位看一次**：反光环境下往往更糟 |
| "加我们的 Logo" | ✅ 允许，顶栏左上，高度 ≤ 40px，**不得占用桌号/时长区域** |


### 17.1 铺满整屏 + 行列数驱动布局（**不滚动，超出分页**）

> **一句话**：**屏幕被切成固定的"列数 × 行数"格子，铺满整屏；格子放不下的内容走分页，永不滚动。**
> 行列数与字号都是**显式配置**（见 §17.6 屏端设置页），不是靠 CSS 自动流式换列。

**整屏三段式（高度分配固定）**

```
┌────────────────────────────────────────────────────────────┐
│ 页头（固定高）  筛选 / 视图 Tab / 操作人 / 时钟             │  ← 64px
├────────────────────────────────────────────────────────────┤
│                                                            │
│  内容网格 = 列数 × 行数（flex:1 吃掉剩余高度，不滚动）      │  ← 剩余全部
│  每格宽 = (可用宽 − 间距×(列−1)) / 列数                     │
│  每格高 = (可用高 − 间距×(行−1)) / 行数                     │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ 页脚（固定高）  第 N / M 页   [◀ 上一页] [下一页 ▶]         │  ← 72px
└────────────────────────────────────────────────────────────┘
```

| 规则 | 说明 |
|------|------|
| **铺满** | 网格 `flex:1`，`overflow:hidden`；页头页脚固定高；**任何区域都不出现滚动条** |
| **格子尺寸** | 由「列数 × 行数」反算，**同屏所有格子等宽等高**（不留半格） |
| **超出** | 走**分页**（页脚页码 + 前后页按钮）；**不滚动** |
| **未满** | 空格子**不渲染**，但网格尺寸不变（保持对齐） |
| **行列上限** | 列 2~12、行 1~10（超出范围配置校验拒绝）；**格子最小 200×140**，小于此值提示"列数过多" |

**两套行列配置（按当前视图生效）**

| 视图 | 列/行配置 | 截图默认值 | 说明 |
|------|-----------|:----------:|------|
| **桌台模式**（菜品汇总/单品显示等） | `DishColumns` × `DishRows` | **8 × 6** | 一个桌台卡 / 一个菜品卡占 1 格 |
| **订单模式** | `OrderColumns` × `OrderRows` | **2 × 2** | 一个订单占 1 格（内容多，格子少） |

> 截图中订单模式还给了 `(1024分辨率建议3列显示)` / `(建议行数2行显示)` 的**辅助提示**——说明连**建议值随分辨率变**。V1 做成"输入框 + 建议值提示"，不做自动改。

**字号三级（`FontScale = S / M / L`）—— 只有这三档，且上限收紧**

> **不开放任意像素值**。截图里是 `菜品字号(像素) 15px` 下拉，我们收敛为**三档**——理由见 §1.5.2：字号是安全下限，开放任意值等于允许门店改到看不清。
> **同时不设"超大/实施档"**：三档就是全部。**菜名上限 32px、桌号上限 40px** —— 再大会一屏放不下几张卡，反而更慢。

| 档位 | 菜名 | 桌号 | 时长 | 徽标 | 行高 | 适用 |
|:----:|:----:|:----:|:----:|:----:|:----:|------|
| **S（小）** | 24px | 32px | 20px | 16px | 64px | 1920 上想一屏看更多卡 |
| **M（中，默认）** | **28px** | **36px** | **24px** | **18px** | **76px** | 标准 |
| **L（大）** | **32px** | **40px** | 26px | 20px | **86px** | 略远 / 老花。**已到上限，不再提供更大档** |

| 约束 | 说明 |
|------|------|
| **硬上限** | 菜名 **≤ 32px**、桌号 **≤ 40px**。任何配置都不能突破（字号过大 = 一屏卡变少 = 翻页变多 = 更慢） |
| 三档与行列数**联动校验** | 选 `L` 时若格子高 < 86px，提示"当前行数下 L 档过大，建议减少行数或选 M" |
| 订单模式另有 `CardSize`（小/中/大） | 卡片**内边距与菜名行数**不同，与 `FontScale` 独立 |
| 屏端设置页可改 | 属 `TerminalConfig`，每屏独立（§17.6） |

**显示顺序（两种模式都适用，`DishSortMode`）**

| 取值 | 排序 | 适用 |
|------|------|------|
| **`OrderSeq`（下单顺序）** | 按下单时间升序（先点先做） | 默认；正餐 |
| **`ItemTypeSeq`（品项类型顺序）** | 先按 `DishType.SortOrder`，再按下单时间 | 烧烤、包子、大众餐（同品类集中做） |

> 排序只改**展示顺序**，不改分页归属的稳定性——**翻页时不允许格子内容跳动**（同一页内顺序固定，翻页后才重排）。

**实现方式（rem 仍保留，但主驱动是行列数）**

```css
:root{ --grid-cols:8; --grid-rows:6; --gap:16px;
       --fs-dish:28px; --row-h:76px; }        /* 由 FontScale 决定 */
.screen-body{ height:calc(100vh - 64px - 72px); overflow:hidden; }
.grid{
  display:grid; height:100%;
  grid-template-columns:repeat(var(--grid-cols), 1fr);
  grid-template-rows:repeat(var(--grid-rows), 1fr);   /* 等分行高，铺满 */
  gap:var(--gap); overflow:hidden;
}
```

> **1080p 浮动缩放（原 §17.1 的 rem 方案）退为"次选"**：只有当屏幕分辨率**不是配置的基准分辨率**时（如 1366×768 而配置按 1920 算），才用根字号 `clamp(12px, 100vw*16/1920, 20px)` 做整体缩放兜底；**正常情况下行列数已经决定了布局，不需要流式缩放**。

**旧方案（media query 自动换列）为什么废弃**：自动换列会让"一屏看几张卡"随窗口大小变化，师傅换个分辨率就找不到原来那张卡了。**固定行列数 + 分页，位置才稳定**。

| 项 | 规则 |
|----|------|
| 卡片高度 | **同屏同高**（由行数等分），避免网格参差 |
| 余量 | 行列数固定，**不因内容多少改列数**；内容不够就是空格 |
| 分页 | 每页容量 = **列数 × 行数**，页数 = `ceil(总条数 / 容量)` |


### 17.2 滚动条规范（**首选不要滚动**）

**四条避免滚动的策略（按优先级）**

| # | 策略 | 适用 |
|:-:|------|------|
| **①** | **分页代替滚动** | 卡片网格、单菜视图、管理端表格 |
| **②** | **卡内折叠代替滚动**（明细 > 8 行显示 `+N 道`，点击展开全屏/抽屉） | 桌台卡、合菜卡 |
| **③** | **缩小字号（到下限）** | 见 §17.1 |
| **④** | **减列数** | 见 §17.1 |
| ⑤ | 最后才用**容器内滚动**（且必须按下列规范） | 抽屉列表、日志列表、长表单 |

**分页条规格（替代滚动的正解）**

```
┌──────────────────────────────────────────────────┐
│                 ... 卡片网格 ...                  │
├──────────────────────────────────────────────────┤
│  [ ◀ 上一页 ]     第 2 / 5 页     [ 下一页 ▶ ]   │  ← 高 64px，按钮 ≥ 160×64
└──────────────────────────────────────────────────┘
```

| 项 | 规格 |
|----|------|
| 位置 | 内容区**底部固定**（不随内容滚动） |
| 按钮 | **≥ 160 × 64**，文字 + 箭头；首/末页置灰 |
| 页码 | "第 N / M 页"，居中，20px |
| 快捷键 | 管理端支持 `←` `→`；触摸屏不做手势（易误触） |
| 自动翻页 | **不做**。后厨屏自动翻页会导致"菜没了"的错觉 |

**若必须用滚动容器（策略⑤）**

```css
.scroll{
  overflow-y:auto; overflow-x:hidden;
  scrollbar-width:thin;                                  /* Firefox */
  scrollbar-color: var(--text-secondary) transparent;
  -webkit-overflow-scrolling:touch;
}
/* Chromium：平时 6px 细条且透明，hover/触摸才显形 */
.scroll::-webkit-scrollbar{ width:6px; }
.scroll::-webkit-scrollbar-track{ background:transparent; }
.scroll::-webkit-scrollbar-thumb{
  background:var(--text-secondary); border-radius:3px; opacity:0; transition:opacity .15s;
}
```

### 17.4 虚拟键盘规范（**数字键盘自绘，全键盘用系统输入法**）

> **关键取舍**：**数字键盘必须自绘**（触摸友好、无歧义）；**文本输入一律调系统输入法**——因为中文候选词无法自绘，自绘全键盘做出来也打不出中文。

**① 数字键盘（自绘）—— 用于 PIN、数量、份数**

```
┌──────────────────────────────────────────┐
│  当前输入：  2 份                    [清空]│
├─────────┬─────────┬──────────────────────┤
│    7    │    8    │    9                 │
├─────────┼─────────┼──────────────────────┤
│    4    │    5    │    6                 │
├─────────┼─────────┼──────────────────────┤
│    1    │    2    │    3                 │
├─────────┼─────────┼──────────┬───────────┤
│    .    │    0    │    ⌫     │   确定    │
└─────────┴─────────┴──────────┴───────────┘
              键盘区高 ≈ 屏高 38%
```

| 项 | 规格 |
|----|------|
| 键尺寸 | **≥ 96 × 96**（触摸），间距 8px |
| 布局 | **3 列 4 行**；`.` 只在**称重菜**出现（整数份数隐藏，避免配错） |
| 位置 | **底部固定**，从下往上推入；内容区自动上移避让 |
| 特殊键 | `⌫` 退格、`清空`、`确定`（右下角，品牌蓝，占 2 格宽） |
| 上限 | PIN 6 位；数量 ≤ 999（超限按键置灰并提示） |
| 禁止 | ❌ 不做"长按连加"（容易加过头）；用 ⌫ 逐位删 |

**② 文本输入（调系统输入法）—— 用于搜索、账号、备注**

| 场景 | 做法 |
|------|------|
| 搜索菜名/桌号 | `input[type=text]` + `inputmode=search`，唤起**系统输入法** |
| 账号输入（管理端登录） | 同上 |
| 备注 / 原因 | 多行 `textarea`，系统输入法 |
| 为什么要系统输入法 | **中文候选词/拼音联想只有系统输入法能做到**；自绘全键盘只能打英文数字，对中餐门店等于废掉 |
| 遮罩避让 | 系统输入法弹出时，**弹窗/输入框自动上移到可视区**（`scrollIntoView({block:'center'})`） |

**③ 数字与文本混用（如"桌号搜索"）**

| 做法 | 说明 |
|------|------|
| 统一用系统输入法，但 `inputmode="numeric"` | 系统会弹数字键盘，且能切回字母 |
| **不**在同一个输入框上自绘键盘 | 自绘键盘只用于**纯数字场景**（PIN、份数） |

**④ 键盘与弹窗的关系**

| 场景 | 处理 |
|------|------|
| 弹窗内输入份数 | 弹窗**整体上移**，数字键盘占底部；弹窗高度自适应且**不超过可见区** |
| 弹窗内搜索 | 系统输入法弹出 → 弹窗上移，标题保持可见 |
| 屏登录（PIN） | 密码框 + **自绘数字键盘**（屏上无系统输入法时也能用） |

**`SearchBumpWholeTable` 的两步确认（**v6.93 定稿**）**

> **原则：把"跳转"和"执行"分开。** 一次输入就产生副作用（划单）是不可接受的——摸错键、看错桌号、索引打错一位，都会划错桌。

```
输入索引（如 "05" 或 "A05"）→ 回车
  ├─ 只做【定位】：把匹配到的桌台卡片**滚动到可视区并高亮选中**（不划任何东西）
  ├─ 若匹配到多张（A05 / A051）→ 弹选择列表，让人挑
  └─ 若匹配不到 → 提示"未找到"，焦点留在搜索框

再按一次回车（或点该卡卡尾【划菜】）→ 才真正划单
  └─ 若 ConfirmWholeTable = 1，还要过这道弹框确认
```

| 规则 | 说明 |
|------|------|
| 首次回车 | **绝对不改数据**（只选中） |
| 二次执行 | 回车 或 点【划菜】；**两次之间有任何其他输入则重置** |
| 超时重置 | 选中态 **5 秒**无操作自动取消选中（防止"忘了自己选过"误按回车） |
| 多匹配 | 弹列表选一个（**不自动取第一个**） |
| 无匹配 | 提示 + 焦点留在搜索框，**不选任何卡** |

**数据库连接区（**仅 Master 本机**显示，对应截图 2）**

| 服务器地址 / 用户名 / 密码 / 数据库名称 | 手工填写 |

**B-01 登录页**（同 §13.11.6 管理端版）：账号 / 密码 / 记住账号（**不记密码**）/ 登录 / 语言 / 版本；**仅未初始化时**底部显示【初始化配置】。

**B-02 初始化向导（5 步，顶部步骤条）**

```
① 语言与地区 → ② 门店信息 → ③ 数据库 → ④ 营业日与餐段 → ⑤ 创建管理员
```

| 步 | 关键控件 | 硬规则 |
|:--:|----------|--------|
| 1 | 语言单选（zh-CN/en-US/zh-TW）；**时区只读**（取本机） | 时区配错极难发现 → 不给改 |
| 2 | 门店编码 / 名称 / 业态单选（正餐·快餐·火锅·饮品） | **编码创建后不可改**；业态只影响默认值预设 |
| 3 | 数据库：SQLite / SQL Server 单选；SQL Server 展开连接表单 +【测试连接】 | **12 项检测**（§5.2），Error 阻断 |
| 4 | 营业日边界下拉（**高亮提示"夜宵店请改"**）+ 餐段复选 + 超时阈值 | 餐段必须构成完整分区 |
| 5 | 账号 / 显示名 / 密码 / 确认密码 + "我已记录密码"勾选 | 禁默认弱口令 |

> 底部固定：`[上一步] [下一步]`；最后一步为 `[完成初始化]`，执行建库/迁移/种子并显示进度条。
