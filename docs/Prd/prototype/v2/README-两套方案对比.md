# KDS 作业屏 UI 原型 · 两套方案对比与选型指南

> 打开 `index.html` 可在两套方案间一键切换比稿。每套均为 **1920×1080 真实像素**、**可交互**、**等比缩放到窗口**。
> 依据：`KDS-04-屏幕视图与UI规格.md` §3（三视图）、`KDS-UI清单与原型说明.md` §1.4（色板）+ §17.1–§17.4（网格 / 滚动 / 弹窗 / 键盘）。

## 一、两套方案的共同底座（不因选型而改变）

### 1. 触摸优先
| 项 | 规格 | 本原型实测 |
|---|---|---|
| 最小点击区 | 48×48 | **≥ 56×56**（A）/ **≥ 60×60**（B） |
| 菜品行高 | ≥ 64px | **68px**（A）/ **78px**（B） |
| 按钮高度 | ≥ 64px | 56→60px 卡内 / 64→68px 分页 / 96→100px 数字键 |
| 划单交互 | 单击即划，**无确认框、无 Toast** | ✅ 整行可点，划完置灰淡出；失败闪红回原位 |
| 悬浮（hover） | 触摸屏不存在，**hover 不承担任何信息** | ✅ 全部状态常驻显示 |

### 2. 无滚动条（四级规避 + 第五级兜底）
```
① 分页代替滚动   ← 桌台网格 / 单菜清单 / 合菜卡片：走底部「第 N / M 页」+ 上一页/下一页
② 卡内折叠        ← 明细 > 4 行显示「+N 道，双击卡片展开」
③ 缩小字号（到 S 档下限）
④ 减列数
⑤ 容器内滚动      ← 仅「组件总览 / 抽屉列表 / 长表单」，且必须按下述规范
```
**第 ⑤ 级规范（原型内已实现，见「组件与状态总览」第 ④ 块）**
- 滚动条 **6px 细条 + 透明轨道**，默认 `opacity:0`，**鼠标移入 / 触摸滚动时才显形**（`.scroll:hover::-webkit-scrollbar-thumb`）
- **强制配一对 ▲▼ 翻屏按钮**：72×72，滚动容器右侧居中浮动，距右 8–10px
- 单击滚半屏；**按住连续滚动**（60ms 步进，300ms 后加速到 90px/帧）
- 到顶 ▲ 置灰、到底 ▼ 置灰
- 原因：触摸屏上 6px 细条点不中，**按钮才是可靠的滚动手段**

### 3. 状态不只靠颜色（色盲 + 强反光双保险）
每个状态都有**徽标文字**：超时 / 将超时 / 催 / 加急 / 等叫 / 起菜 / 赠 / 退 / 损 / 跨日 N 天 / 已沽清 / 完成 / 2/3 / 1.25kg。
另配 **左侧 6px 实心色条 + 卡片底色**，共三重编码。

## 二、方案 A · 夜航控制台（Dark · 高密度）

| 维度 | 取值 |
|---|---|
| 适用环境 | 暗厨房 / 夜宵档 / 传菜口暗区 / 只有备餐灯 |
| 页面底 | `#0E1116`（**不用纯黑**——LCD 上纯黑+白字产生光晕，长时间看更累） |
| 卡片底 | `#191D25` |
| 正文 | `#E9EDF2`，对比度 **11.8:1** |
| 品牌/高亮 | `#4C9AFF` |
| **桌台网格** | **4 列 × 2 行 = 8 卡/页** |
| 合菜网格 | 5 列 × 4 行 = 20 卡/页 |
| 单菜 | 10 行/页 |
| 字号 | 桌号 36 · 菜名 28 · 份数 28 · 时长 24 · 徽标 18 |
| 页头 / 页脚 | 72px / 88px |

**气质**：信息密度优先、暗色降低长时间注视疲劳、状态色在暗底上更醒目（催菜呼吸闪烁尤其明显）。
**代价**：一屏卡片多 → 单卡信息量略少（每卡最多 4 行明细）。

## 三、方案 B · 晨光大卡片（Light · 可读性优先）

| 维度 | 取值 |
|---|---|
| 适用环境 | 明亮后厨（灶台灯）/ 强反光 / 老屏 / 远距离 / 师傅老花眼 |
| 页面底 | `#EEF2F7`（强对比档切 `#FFFFFF`） |
| 卡片底 | `#FFFFFF` |
| 正文 | `#14181F`，对比度 **15.3:1**（强对比档 `#000`，**21:1**） |
| 品牌/高亮 | `#1A6DFF` |
| **桌台网格** | **3 列 × 2 行 = 6 卡/页** |
| 合菜网格 | 4 列 × 3 行 = 12 卡/页 |
| 单菜 | 9 行/页 |
| 字号 | 桌号 **40**（品牌色实底块）· 菜名 **30** · 份数 30 · 时长 26 · 徽标 19 |
| 页头 / 页脚 | 80px / 96px |

**气质**：留白宽松、桌号做成**品牌色实底块**（远距离第一落点）、菜品行是独立白卡片（划单边界清晰）。
**额外能力**：右上角可切 **「强对比」档**（纯白底 + 纯黑字 + 字重 +1 + 边框加粗），对应 §1.5.1 的第二档环境适配。
**代价**：一屏卡片少 → 桌台多时翻页更频繁。

## 四、选型建议

| 门店特征 | 推荐 | 理由 |
|---|---|---|
| 灶台灯很亮、有反光 / 师傅老花 / 老屏 | **B（+ 强对比档）** | 大字大卡 + 21:1 对比 |
| 夜宵档、传菜口偏暗、24h 店 | **A** | 暗底不刺眼，暗环境对比更稳 |
| 桌台数多（>15 桌在制） | **A** | 8 卡/页，翻页次数少 |
| 桌台少但每桌菜多（正餐/宴席） | **B** | 6 卡/页，每卡能放 4 行且行更高 |
| 传菜屏 / Expo（远距离看桌号） | **B** | 40px 桌号实底块，5 米外可辨 |
| 切配/制作屏（近距离操作） | **A** | 密度优先，减少翻页 |

> 两套方案 **共用同一套 token 命名与组件结构**，切换只换 `:root` 变量层，**组件代码零改动**（§1.5.4 三层 token：Primitive → Semantic → Component）。
> 因此可以做成「每块屏独立选显示模式」（落在 `TerminalConfig.DisplayMode`，不是 `StoreConfig`）——同一家店灶台区用 B、传菜口用 A 完全可行。

## 五、原型内含的 5 屏

| 屏 | 内容 | 可交互点 |
|---|---|---|
| A-01 登录 | 表单 + 自绘数字键盘（PIN） | 数字键可点 |
| **A-02 桌台视图** | 12 桌分页（A:8/页，B:6/页） | **点菜品行 = 划单**；【划菜】整卡划完并消失；【叫号】弹视觉反馈；【换人】【我的划单记录】抽屉；【退出】危险对话框 |
| A-03 合菜视图 | 左聚合卡 + 右明细批量栏 | 点左卡联动右栏；右栏勾选 → 【选中划】由灰转亮；▲▼ 翻屏 |
| A-04 单菜视图 | 平铺清单，按时长倒序 | 整行点击划单；上下页 |
| 组件与状态总览 | C1 菜品行 14 态 / C9 徽标全集 / C2 卡片 4 态 / C11 滚动容器 / C12 数字键盘 / C7 对话框 | **滚动条 hover 显形 + ▲▼ 长按连续滚动** |

原型导航条右上角另有：
- **密度切换**（标准 ↔ 紧凑，紧凑只缩间距，行高不低于 60px）
- **对比切换**（仅方案 B：标准 ↔ 强对比）

## 六、与文档规格的偏差说明（3 处，均为触摸优先下的主动上调）

| 项 | 文档值 | 原型值 | 理由 |
|---|---|---|---|
| 页头高度 | 64px（§17.1） | **72px（A）/ 80px（B）** | 容纳 52px 高的 Tab 与筛选 chip，保持 ≥48px 触摸区 |
| 分页条高度 | 64px（§1.8） | **88px（A）/ 96px（B）** | 按钮 64→68px + 上下留白，避免贴边误触 |
| 卡尾按钮 | — | **56→60px 高、112→120px 宽** | 文档要求 ≥48×48，实测 56 以上才适合戴手套点击 |
