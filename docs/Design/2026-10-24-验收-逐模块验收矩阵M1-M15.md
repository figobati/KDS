# 逐模块验收矩阵 M1–M15（V1）

> **需求来源**：用户 2026-10-24「逐模块验收矩阵 M1–M15，出吧」
> **PRD 依据**：`KDS-01` §1.5 命名表 + §1.6 D1–D17；`KDS-02`–`KDS-13` 各模块主责章节；`KDS-13` §15 测试约定；`schema/` 机器真值；两份 DDL
> **基线版本**：PRD **v6.99** · 语言包 761 key × 3 语
> **结论**：**15 个模块 / 134 条模块级验收用例（P0 103 / P1 27 / P2 4）+ 12 条通用门禁 + 9 条跨模块集成验收**。模块"完成"的判据 = **该模块 P0 用例全绿 + 通用门禁 G1–G12 全绿 + 无前序回归**，三者缺一不算完成。

## 1. 这份矩阵解决什么问题

现有的验收材料只有三种，**都不回答"某个模块算不算做完了"**：

| 现有材料 | 它回答什么 | 缺口 |
|:---|:---|:---|
| `KDS-实施检查表.md` | 门店装店时怎么验（现场 SOP） | 是**交付后**的验收，不是**开发中**的完成判据 |
| `schema/` 24 条契约测试 | 事件格式对不对 | 只覆盖 M2，覆盖不到状态机 / 归集 / 同步 / UI |
| `KDS-10` §13.4 NFR 指标 | 性能达不达标 | 只测"快不快"，不测"对不对" |

所以本矩阵的定位是：**每个模块交付时，程序员自检 + 质审复核 + 架构师确认，三人都用同一张表**。

## 2. 验收分层

| 层 | 名称 | 何时跑 | 谁签字 |
|:-:|:---|:---|:---|
| **L0** | 通用门禁 | 每次提交 / CI | 自动化，红灯即退 |
| **L1** | 模块验收用例 | 模块交付时 | 程序员自检 → 质审复核 → 架构师确认 |
| **L2** | 跨模块集成验收 | 相关模块都完成后 | 架构师 |
| **L3** | 门店装店验收 | 上线前现场 | 实施 + 门店 |

本矩阵覆盖 **L0 / L1 / L2**；L3 已有 `KDS-实施检查表.md`，不重复。

## 3. 判定规则

### 3.1 用例等级

| 等级 | 含义 | 未通过时 |
|:---:|:---|:---|
| **P0** | 阻塞。口径错、数据错、账务错、安全漏洞 | **模块不算完成**，必须修完重跑 |
| **P1** | 重要。功能可用但有明显缺陷或体验损伤 | 可带缺陷交付，但**必须登记缺陷号 + 影响面 + 期限**，架构师签字 |
| **P2** | 优化。性能余量、文案打磨、日志详略 | 记入待办，不进本次判定 |

### 3.2 模块完成判据（三条全中才算完成）

```
① 该模块 P0 用例 100% 通过（有原始输出，不接受截图/摘要）
② 通用门禁 G1–G12 全绿
③ 前序模块用例无回归（重跑仍全绿）
```

### 3.3 什么不算完成（常见误判，直接退回）

| 情形 | 为什么不算 |
|:---|:---|
| 评分 ≥80 但有 P0 用例未过 | 评分衡量的是一致性，不是需求达成 |
| 功能能跑，但没有 `dotnet test` 原始输出 | 不可验证 = 未完成 |
| P0 用例用"手工点了一遍"代替自动测试 | 无回归保护，下个模块一改就碎 |
| 只改了 PRD 一处口径，没同步 D 表 | 口径分叉，后续必然返工 |
| 双引擎只验了 SQLite | SQL Server 是付费客户的主场景，不能只测一半 |
