# 语言包 Key 清单（V1 冻结基线）

> **需求来源**：用户 2026-10-24「先出语言包 key 清单」
> **PRD 依据**：`KDS-09-多语言与国际化.md` §11.0–§11.7（三层分离 / 命名规范 / 回退链 / 自检 9 项）、`KDS-UI清单与原型说明.md` §2（38 屏）、`KDS-07` §9.1 / §9.2（配置字段）、`KDS-08` §10.6（错误码）、`KDS-03` §2.17.1（报损原因）、`KDS-04` §3（作业屏）、`KDS-10` §13（管理端 / 向导）
> **版本**：v1.0 · 基线对照 PRD **v6.99**
> **结论**：V1 共 **761** 个 key、13 个命名空间，**三语（zh-CN / en-US / zh-TW）全部落地**（见 §7）。**契约与 DDL 零改动**——本清单只新增语言资源，不动表、不动事件、不动状态机。

**四条硬约束（进验收）**

1. **禁止硬编码中文**——所有界面文案必须来自本文 key（§14 硬约束 14）。
2. **zh-TW 必须由繁体母语人工复核后才能上线**——机转初稿只算 `draft`，「禁止自动转换」禁的是「未经人审就进生产包」（§11.6 / 本文 §7.4）。
3. **占位符集合跨语言必须完全一致**，不一致 = 构建失败（§11.7.2 定为 Error）。
4. **缺 key 不得显示 key 名**——按 `当前语言 → 门店默认 → zh-CN → 原始值` 回退（§11.1）。


### 2.3 与 §11.1 示例的偏差（**需登记**）

§11.1 原文示例为 `screen.cook.newOrder`。V1 **实际采用 `scr.*`** 而非 `screen.*`，原因：`screen` 与 `TerminalConfig` 的"屏幕"语义、`ScreenLogin` 混淆，且 6 字符前缀在 761 条里多耗 1KB 体积、扫描时干扰视线。

> **处理**：本文生效后回头把 §11.1 的示例改成 `scr.card.newOrder`，保持文档与实现一致（见 §10 待办 T-1）。

### 2.4 字段类 key 的机械转换规则（`cfg.*`）

| 原名形态 | key 段 | 例 |
|:---|:---|:---|
| PascalCase | 首字母小写 | `EnableWorkflowState` → `enableWorkflowState` |
| 含下划线（`TerminalConfig` 遗留） | 去下划线转 lowerCamel | `Merge_LinkedTable` → `mergeLinkedTable` |
| | | `Merge_LinkedTable_CrossArea` → `mergeLinkedTableCrossArea` |
| | | `ItemView_SortMode` → `itemViewSortMode` |
| 每个字段两段 | `.label`（短标签，≤24 字）+ `.hint`（提示，PRD 说明原文裁剪） | `cfg.store.flowMode.label` / `.hint` |

**为什么必须有 `.hint`**：`StoreConfig` 有 72 个字段，其中 `FlowMode`、`UndoScope`、`LocalHistoryMode` 这类**单看标签无法理解**的枚举，必须配一句说明，否则运维会按直觉配错（例：把"归集主语言"当成"显示语言"）。

### 2.5 禁止项（进 CI 检查）

| # | 禁止 | 理由 |
|:-:|:---|:---|
| 1 | 文案里硬编码数字 | 数字必须走占位符，否则改阈值要改三个语言包 |
| 2 | 文案里带单位标点（`12 分钟`） | 单位走 `common.unit.*`，中英单位长度差异大 |
| 3 | 同一语义在多个命名空间重复定义 | 改一处漏两处 |
| 4 | 把整段说明塞进按钮词条（>200 字符） | 撑破布局（§11.5.2 规则 2） |
| 5 | 用 key 名兜底展示 | 后厨屏显示 `common.action.complete` = 师傅不知道点哪个 |
| 6 | 为英文"顺口"改中文基准值 | zh-CN 是基准，翻译向它靠，不是反过来 |

## 3. 占位符与数字格式（**三条决策，已定**）

### D-I18N-1 只用命名式占位符

| 写法 | 判定 |
|:---|:---|
| `{name}`、`{n}`、`{qty}`、`{duration}` | ✅ 唯一允许 |
| `{0}` / `{1}` | ❌ 禁止（§11.7 检查器仍兼容，但**新词条一律命名式**） |

**理由**：位置式占位符在译文里长句重排后极易错位，而错位在 §11.7.2 里是 **Error 级**（运行期抛异常）。命名式让译者在句子任意位置放 `{n}`，不会错。

### D-I18N-2 不做复数变形，用不变单位

中餐后厨的"份"在英文里没有干净对应（`portion` / `serving` / `pcs`）。V1 决策：**用不随数量变化的短单位**，规避 ICU 复数语法。

| 场景 | zh-CN | en-US |
|:---|:---|:---|
| 份数 | `{qty} 份` | `{qty} pcs` |
| 分钟 | `{n} 分钟` | `{n} min` |
| 桌数 | `{n} 桌` | `{n} tables`（仅此处允许 `tables`，因桌数固定 >1 场景） |

**必须用复数的少数场景**（如 `1 item` / `2 items`）用**成对 key**，检查器视为一组，允许只填 `_other`：

```
common.label.itemCount.one    → "{n} 道菜"
common.label.itemCount.other  → "{n} 道菜"
```

> `zh-CN` / `zh-TW` 两个值恒等（中文无复数），`en-US` 才区分。

### D-I18N-3 数字 / 时间 / 日期不吃 locale（§11.5.4 已定，此处落到 key）

| 项 | 规则 | 对应 key |
|:---|:---|:---|
| 时间 | **固定 `HH:mm:ss` 24 小时制**，不随语言变 12 小时 | 不入语言包，纯格式化代码 |
| 日期 | **固定 `YYYY-MM-DD`** | 同上；唯一例外是报表列头 `report.col.businessDate` 的**标签** |
| 时长 | 走语言包拼装，不拼字符串 | `time.waitFor` / `time.overdueBy` / `time.stageElapsed` / `time.totalElapsed` |
| 份数 | **不带千分位** | `common.unit.piece` |
| 计时器 | 等宽字形 `tabular-nums` | 非文案，属 CSS |

**时长格式化必须只有一个出口**：`{duration}` 由 `FormatDuration()` 统一产出（`1分05秒` / `1m 05s`），语言包只负责句子模板，不负责单位拼接。

### 7.2 en-US 术语决策（餐饮行话，不是词典直译）

> 后厨英语有自己的行话。直译出来"能看懂但不像行内人说的话"，师傅培训成本反而更高。

| zh-CN | en-US | 为什么不是直译 |
|:---|:---|:---|
| **划单** | **Bump** | 欧美后厨标准行话 `bump the ticket`。译成 `Complete` 会与"订单完成/结账"混淆；4 字符 vs 8 字符 |
| **划单记录** | **My Bumps** | 同上，`Bump` 作名词在 KDS 界面通用 |
| **沽清** | **86** | 行话 `86 it`（卖完）。徽标位只有 3 字符，`Sold Out` 放不下；**徽标用 `86`、句子用 `sold out`** 两套并存 |
| **传菜 / 传菜屏** | **Expo / Pass** | `Expo` = expediter，就是传菜岗；与 `Prep` `Cook` 构成标准三岗 |
| **份** | **pcs** | 不用 `portion`/`serving`（长且不可数）；配合 D-I18N-2 规避复数 |
| **人数** | **pax** | 餐饮行话（`2 pax`），比 `guests` 短一半，卡片省空间 |
| **催菜 / 加急** | **URGE / RUSH** | 徽标位全大写短词；`Rush` 是加急标准说法 |
| **报损** | **Written Off / LOSS** | 财务术语 `write-off` 最准；徽标位用 `LOSS` |
| **跨日** | **XDAY** | 徽标位 3 字符；正式句子仍写 `cross-day` |
| **档口** | **Station** | 与 `Terminal`（设备）区分清楚 |
| **合菜视图** | **Merge** | 指"同一菜品跨桌合并"，比 `Aggregate` 短且是 POS 通用词 |

**三条英文侧硬约束**

1. **按钮词条 ≤ 2 个单词**（超了改「图标 + 短词」），否则档 B 的 ×2.5 也压不住。
2. **徽标位只允许 ≤ 4 字符全大写**：`CXL` `GIFT` `URGE` `RUSH` `HOLD` `FIRE` `LOSS` `XDAY` `NEW` `86` `WT`。
3. **不用缩写点**（`Order No.` 例外，是标准写法），不用 `&` 代替 `and`（`Save & Close` 等惯用除外）。

| 重叫 | Call Again | 2.50x |

**为什么短标签反而更危险**：中文 2 个字承载的信息，英文要 8~12 字符。而厨房屏恰恰**以短标签为主**（PRD §1.2 要求极简、2 米外可读），所以档 B 才是主战场；长句（hint / 说明）膨胀收敛在 1.2~1.5x，×1.5 本来就够。

### 11.3 已据此修正 PRD §11.5.1（两档基线）

| 档 | 适用范围 | 预留宽度 | 实测依据 |

| **档 A** | 长文本（≥8 汉字：说明、hint、提示句） | **×1.5** | 中位 1.25~1.50，够 |
| **档 B** | 短标签（≤4 汉字：按钮 / Tab / 筛选 chip） | **×2.5**，或改「图标 + 短词」 | 中位 1.38，P95 2.25，须留 2.5 |
